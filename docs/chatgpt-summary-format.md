# ChatGPT 用サマリ — 粒度標準（Cursor 必読）

オーナーは **`docs/chatgpt-summary.md` の内容だけ** を ChatGPT に貼る。  
**薄い要点メモは不可。** 下記粒度を満たすこと。

---

## 禁止（薄いメモ）

- 各 `■` が1行だけ
- 「詳細は docs/xxx を参照」だけで中身を省略
- ロードマップ・判断・理由・スコープを圧縮しすぎる
- オーナー判断・技術前提・次アクションが抜ける

---

## 必須（厚いメモ）

1. **`docs/chatgpt-summary.md` を更新**（プレーンテキスト、`■` 見出し、表・`#`・`---` 不可）
2. **レスポンス末尾に同一内容の ` ```text ` ブロック**（Copy ボタンが主経路）
3. **両方の内容は同一**

---

## 最低限含めるセクション

作業種別に応じて **該当するものはすべて** 書く。省略は「該当なし」と1行書く。

### 常に（Forge 関連の返答）

```
■ 現在の状態
- 本番 URL / 最新 commit（分かる場合）
- DB migration 状態
- 直近で確定したオーナー判断（箇条書き、理由1行ずつ）
- フェーズ認識（例：致命的UX解消済み / 次テーマ検討中）

■ Forge原典コアループ（判断の基準）
- 1行でループを書く
- 今回の話がループのどこに触れるか1〜2行
```

### ロードマップ・優先順位・整理タスクのとき **追加必須**

```
■ MVPとして最低限（実装済み）
- 領域ごとに1行（発見/プレイ/FB/投稿/devlog/004/開発ダッシュボード等）

■ 未実装の重要機能
- 【最重要】【中】等の優先度ラベル
- 各項目2行以上（何が未実装か + なぜ重要か）

■ 実装済みだが弱い機能
- 各項目1〜2行（弱さの具体）

■ 後回しでよい機能
- 箇条書き（P1 copy、新規page、AI等）

■ 現在地
【完成している】- 箇条書き
【未完成】- 箇条書き

■ リリース前に必須 / リリース後でもよい
- 各項目に理由1行

■ 次に着手すべき1テーマ（Cursor推奨1位のみ）
- テーマ名
- 内容（何をするか3行以内）
- なぜ1位か（番号付き5点程度、各2行以内）
- 実装スコープ In / Out

■ 実装したときの効果
- プレイヤー / 開発者 / Forgeコンセプト（各2〜3行）
```

### 実装・deploy・migration のとき **追加**

```
■ 今回実装（または確認）したこと
■ ユーザー目線の変化
■ 注意事項
■ 今すぐ私（オーナー）がやるべきこと
■ Cursorだけで完了できること
```

### 設計判断が絡むとき **追加**

```
■ Cursorの推奨案
■ 推奨理由
■ 懸念点
■ ChatGPTに相談したい論点（具体例3〜5個）
```

### 技術引き継ぎ

```
■ 技術メモ（ChatGPT/Cursor用）
- project_id text、適用済み migration、LS残、関連 doc パス
```

---

## 粒度の目安

| サマリ種別 | 目安行数（■ 見出し除く） |
|---|---|
| 小さな修正・確認のみ | 25行以上 |
| UX / 機能実装完了 | 40行以上 |
| ロードマップ・優先順位整理 | **60行以上** |
| migration + deploy + 判断 | 50行以上 |

**1行に複数論点を詰め込まない。** オーナーが ChatGPT だけで文脈復元できる密度。
