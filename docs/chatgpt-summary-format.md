# ChatGPT 用サマリ — 粒度標準（Cursor 必読）

**恒久ルール**：本ファイルが Forge の GPT 用メモの**唯一の形式標準**。オーナーが「フォーマットを変えたい」と明示するまで、Cursor は**毎セッション・毎タスク**この標準に従う。勝手に薄くしたり、セクションを省略したり、旧形式に戻したりしない。

オーナーは **通常** `docs/chatgpt-summary.md` の内容だけを ChatGPT に貼る。  
**新スレッド開始時** は `docs/chatgpt-handoff.md` を先に貼る（後述）。  
**薄い要点メモは不可。** 下記粒度を満たすこと。

---

## 禁止（薄いメモ）

- 各 `■` が1行だけ
- 「詳細は docs/xxx を参照」だけで中身を省略
- ロードマップ・判断・理由・スコープを圧縮しすぎる
- オーナー判断・技術前提・次アクションが抜ける
- **既存セクション（なぜこの設計 / 他案不採用 / In Out / リスク / オーナー確認手順）を削って画面セクションだけ足す**

---

## 必須（厚いメモ）

1. **`docs/chatgpt-summary.md` を更新**（プレーンテキスト、`■` 見出し、表・`#`・`---` 不可）
2. **レスポンス末尾に同一内容の ` ```text ` ブロック**（Copy ボタンが主経路）
3. **両方の内容は同一**

---

## 2ファイル運用（summary vs handoff）

| ファイル | 更新頻度 | 用途 |
|---|---|---|
| `docs/chatgpt-summary.md` | **毎タスク**上書き | 差分中心。今回何をしたか・設計判断・画面変更 |
| `docs/chatgpt-handoff.md` | **引継ぎトリガー時のみ** | 新 GPT スレッド初回の全量スナップショット |

### chatgpt-handoff.md の更新トリガー

以下のいずれかに該当したら **必ず** `docs/chatgpt-handoff.md` を全量更新する：

1. **大テーマ完了**（例：版公開ループ接続、004 適用完了）
2. **migration 完了**（本番 Dashboard 適用・確認済み）
3. **ロードマップ順位変更**（次テーマの優先順位・Cursor 推奨1位が変わったとき）
4. **オーナーが引継ぎを指示**（「引継ぎ」「新スレッド用」等）

**更新しない**：小修正、copy 調整、build 確認のみ、docs  typo 修正。

新スレッドの貼り付け順：**handoff（1回）→ 以降は summary（差分）のみ**。

## 最低限含めるセクション

作業種別に応じて **該当するものはすべて** 書く。省略は「該当なし」と1行書く。

### 常に（Forge 関連の返答）

```
■ 現在の状態
- 本番 URL / 最新 commit（分かる場合）
- DB migration 状態
- 直近で確定したオーナー判断（箇条書き、理由1行ずつ）
- フェーズ認識（例：致命的UX解消済み / 次テーマ検討中）

■ Forge原典コアループ（判断の基準）
- 1行でループを書く
- 今回の話がループのどこに触れるか1〜2行
```

### ロードマップ・優先順位・整理タスクのとき **追加必須**

```
■ MVPとして最低限（実装済み）
- 領域ごとに1行（発見/プレイ/FB/投稿/devlog/004/開発ダッシュボード等）

■ 未実装の重要機能
- 【最重要】【中】等の優先度ラベル
- 各項目2行以上（何が未実装か + なぜ重要か）

■ 実装済みだが弱い機能
- 各項目1〜2行（弱さの具体）

■ 後回しでよい機能
- 箇条書き（P1 copy、新規page、AI等）

■ 現在地
【完成している】- 箇条書き
【未完成】- 箇条書き

■ リリース前に必須 / リリース後でもよい
- 各項目に理由1行

■ 次に着手すべき1テーマ（Cursor推奨1位のみ）
- テーマ名
- 内容（何をするか3行以内）
- なぜ1位か（番号付き5点程度、各2行以内）
- 実装スコープ In / Out

■ 実装したときの効果
- プレイヤー / 開発者 / Forgeコンセプト（各2〜3行）
```

ロードマップ順位が変わったタスクでは、**chatgpt-handoff.md も更新**（上記トリガー）。

### 実装・deploy・migration のとき **追加**

```
■ 今回実装（または確認）したこと
■ ユーザー目線の変化
■ 今回変更した画面（UI変更があるとき必須。なければ「該当なし（バックエンドのみ）」）
■ 注意事項
■ 今すぐ私（オーナー）がやるべきこと
■ Cursorだけで完了できること
```

### 設計判断が絡むとき **追加**（削らない）

```
■ なぜこの設計にしたか
■ 他案を採用しなかった理由
■ In / Out
■ リスク
■ Cursorの推奨案
■ 推奨理由
■ 懸念点
■ オーナーが確認する手順（5分フロー等）
■ ChatGPTに相談したい論点（具体例3〜5個）
```

### 技術引き継ぎ

```
■ 技術メモ（ChatGPT/Cursor用）
- project_id text、適用済み migration、LS残、関連 doc パス
```

## ■ 今回変更した画面（テンプレート）

**対象は今回変更した画面のみ。** 全画面説明は不要（全画面は `chatgpt-handoff.md`）。

UI 変更がないタスクでは：

```
■ 今回変更した画面
該当なし（バックエンドのみ / migration のみ）
```

UI 変更があるタスクでは、**画面ごとに** 以下ブロックを繰り返す：

```
■ 今回変更した画面

--- 画面1 ---
画面名: （例：通知一覧）
URL: （例：/notifications）
画面位置: （例：通知一覧の各カード先頭 / ヘッダー右上 / 概要セクション直下）
変更前:
- 何が見えていたか（文言・色・有無）
変更後:
- 何が増えた・変わったか
プレイヤー視点:
- どう変わったか（1〜2行）
開発者視点:
- どう変わったか（1〜2行。該当なければ「変更なし」）
確認手順:
- どこを押せば見られるか（ログイン要否、前提データ）

--- 画面2 ---
（同形式。2画面以上ある場合は続ける）
```

**画面位置** の例：概要セクション直下、ヘッダー右上、作品カード内、通知一覧の先頭、FBフォーム上部、開発ダッシュボードの FB 一覧上。

## 粒度の目安

| サマリ種別 | 目安行数（■ 見出し除く） |
|---|---|
| 小さな修正・確認のみ | 25行以上 |
| UX / 機能実装完了 | 40行以上（画面変更ありなら +10行程度） |
| ロードマップ・優先順位整理 | **60行以上** |
| migration + deploy + 判断 | 50行以上 |

**1行に複数論点を詰め込まない。** オーナーが ChatGPT だけで文脈復元できる密度。

## ChatGPT 向けトリガー運用（恒久）

正本: **`docs/forge-triage-operations.md`**（Cursor も参照可）

| トリガー | ChatGPT の動き |
|---|---|
| オーナー **`CURSOR`** のみ | 直前会話を踏まえ Cursor 貼付用 **完成文 1 本**。追記・断片・複数レス禁止。判断未確定なら判断材料のみ |
| Run/Deploy/Migration **スクショ** | Run 判断依頼 → **[A]〜[D]** + Forge価値・ユーザー影響・復旧難易度 |
| summary / handoff / GPT判断用メモ | **レビュー**（現在地・リスク・次アクション・原典整合） |
| UX 違和感（分かりにくい等） | **UX レビュー**。他ユーザーにも起きうるか。プロダクトレビュー優先 |

判断優先順位: Forge原典 → ユーザー価値 → 開発者価値 → MVP成立 → 技術的綺麗さ
