# P1-2.7 ゲーム育成サイクル再設計 — ワイヤーフレーム

**ステータス**: 実装完了（deploy 待ち）  
**前提**: P1-2.6 実装済み。オーナー方向性 GO — **5 ステップ + ↺ ループ** に確定。  
**コード変更**: なし。

**変更履歴**
- v1: 7 ステップ（新しいFB / ループ 独立ノード、「改善する」）
- **v2（本版）**: 5 ステップ、「**改善中**」、新 FB は **反応待ち → FBを読む** の ↺ のみ

## 0. オーナー FB（v2 確定事項）

| 項目 | v1 | v2（確定） |
|---|---|---|
| 改善ステップ | 改善する（イベント） | **改善中**（状態） |
| 新 FB | 独立ノード ⑥ | **なし** — 反応待ち ↺ FBを読む で表現 |
| ループ | 独立ノード ⑦ | **↺ 矢印** のみ |
| 中心ループ | 7 段 | **5 段** |

**「改善する」問題（オーナー指摘）**
- 改善した / 改善中 / 方針検討のみ — **完了判定が不可能**
- **改善中** なら「devlog を書くまでこの状態」で自然

**「新しいFB」問題**
- 独立ノードは冗長
- 新 FB 到着 = **反応待ちが終わり、再び FBを読む へ** — ↺ で十分

## 1. 中心ループ — 5 ステップ

```
    ┌─────────────┐
    │  FBを読む   │◀────────────────────┐
    └──────┬──────┘                     │
           ↓                            │
    ┌─────────────┐                     │
    │   改善中    │  ← 状態（devlog まで）│
    └──────┬──────┘                     │
           ↓                            │  ↺
    ┌─────────────┐                     │
    │開発ログを書く│  ← イベント          │
    └──────┬──────┘                     │
           ↓                            │
    ┌─────────────┐                     │
    │新版公開する │                     │
    └──────┬──────┘                     │
           ↓                            │
    ┌─────────────┐                     │
    │ 反応を待つ  │─────────────────────┘
    └─────────────┘
```

サイクル外（1 行 gray）: `✓投稿 · ✓発見 · ✓プレイ`

## 2. ステップ定義 — イベント vs 状態

| ID | ラベル | 種別 | 意味 | 完了条件 | click → 振り返り |
|---|---|---|---|---|---|
| read | FBを読む | **イベント** | 届いた声を読む | FB 確認済（※） | 今サイクル FB + 過去 |
| improving | 改善中 | **状態** | 方針検討・実装・調整中 | devlog 作成まで | 改善メモ・直す対象・参考 FB |
| devlog | 開発ログを書く | **イベント** | 改善を記録 | 未公開 devlog あり | 今回 + 過去 devlog |
| publish | 新版公開する | **イベント** | 版を届ける | publishedVersion あり | 公開履歴・版号 |
| wait | 反応を待つ | **状態** | 再プレイ・新 FB 待ち | 新 FB 到着（※） | 待機 copy・作品ページ |

（※）soft state — 5-3 参照。新 FB 到着はデータ上 `latestFeedback` の更新で検知 → **read が次** に自動遷移。

**改善中の境界**
- **入る**: FBを読む 完了後
- **出る**: 開発ログを書く 実行後
- その間は方針だけ / 実装中 / 途中 — **すべて「改善中」**

---

## 3. 設計原則（v2）

1. **イベントと状態を混ぜない** — イベント=動詞（読む・書く・公開する）、状態=〜中（改善中・反応待ち）
2. **FBを読むは独立** — 改善中に吸収しない
3. **完了=gray だが click 可能** — 振り返り常時
4. **今 / 次 / 完了** — 次=最強調 + Primary 1 つ
5. **0.5 秒で次** — NurtureHero が主役、Focus Rail は位置づけ
6. **↺ は反応待ち→FBを読む** — 新 FB ノード不要
7. **5 段なら Focus Rail に全ステップ載せられる** — 7 段より一覧向き

## 4. Focus Rail — コンポーネント anatomy

一覧カード内の **位置づけ UI**。NurtureHero の直下。

```
┌─ Focus Rail ─────────────────────────────────────────────────────┐
│                                                                  │
│  [node] → [node] → [node] → [node] → [node]                      │
│   完了     今       次      未到達    未到達                       │
│                                                                  │
│              ╭──────────────────────────────╮                    │
│              │  ↺  反応待ち → FBを読む       │  ← LoopHint       │
│              ╰──────────────────────────────╯                    │
└──────────────────────────────────────────────────────────────────┘
```

### 4-1. ノード chip サイズ（相対）

| 役割 | 幅 | 高さ | スタイル |
|---|---|---|---|
| 完了 | 小（72px） | 低 | gray, ✓, click |
| 今 | 中（88px） | 中 | orange border, 「今」 |
| 次 | **大（104px）** | **高** | ring-2, 「次」, font-bold |
| 未到達 | 小（64px） | 低 | zinc-600, 破線 border |

### 4-2. ラベル短縮（狭画面）

| フル | sm 未満 |
|---|---|
| FBを読む | 読む |
| 改善中 | 改善中 |
| 開発ログを書く | devlog |
| 新版公開する | 公開 |
| 反応を待つ | 待つ |

### 4-3. LoopHint（↺）

- **常時表示**（5 段すべて載るため下部に余白）
- 反応待ち chip の下から曲線 → FBを読む chip へ
- ラベル: `↺ サイクル` または `↺ 次の声へ`
- 新 FB 到着時: LoopHint を **pulse** または `新しい声 →` 1 行（Hero 下、Rail 上）

### 4-4. Focus Rail と NurtureHero の関係

```
┌─ NurtureHero ────────────────────┐
│  次にやること                     │
│  開発ログを書く        ← 28px bold│
│  （改善が終わったら記録）← 12px  │  … 改善中のみ補助行
└──────────────────────────────────┘
┌─ Focus Rail ─────────────────────┐
│  [✓読] [今·改善中] [次·devlog] …  │
└──────────────────────────────────┘
[ Primary: 開発ログを書く ]
```

**Hero = 次の Forge 行動**（最大）  
**Rail = サイクル上の位置**（今・次・完了の文脈）  
**Primary = Hero と同ラベル**（1 つ）

### 5-7. 2 周目時の完了 chip 扱い（オーナー判断）

**案 A — リセット（推奨）**
- 新サイクル開始で read/improving/devlog/publish をすべて未到達に
- 前周の振り返りは **サイクル番号 click** or メタ `サイクル 2 ▼` で過去周表示
- Focus Rail は常に **今周のみ** — 一覧がすっきり

**案 B — 左に縮小履歴**
- `[✓²]` のように dot だけ残し、今周 5 chip を右に
- 複雑 — 非推奨

**ワイヤ推奨: 案 A**

## 7. モバイル — Focus Rail

幅 < 640px: **3 表示 + 省略**

```
  [✓] [今] [次]  +2  ↺
  読  改善  dev

  次にやること
  開発ログを書く

  [ 開発ログを書く ]
```

- 完了 1 + 今 + 次 のみ大きく
- `+2` tap → 5 段フル Rail を bottom sheet
- ↺ アイコンは常に右端

## 9. 状態マッピング（データ → 今/次）

| 条件 | 今 | 次 | Hero |
|---|---|---|---|
| FB 0 | wait | wait | 反応を待つ |
| 新 FB、未 read | — | read | FBを読む |
| read 済、devlog なし | improving | devlog | 開発ログを書く |
| devlog 済、未公開 | devlog※ | publish | 新版公開する |
| 公開済、新 FB なし | wait | wait | 反応を待つ |
| 公開済、新 FB あり | — | read | FBを読む + ↺ active |

※ devlog 済み直後は「今」= devlog 完了表示 or improving から publish へ — **次=publish** を優先。
