# Forge Roadmap（2026-06 正本）

**Cursor / ChatGPT 共有用** — 画面番号順ではなく **工程フェーズ** と **コアループ順** で進める。

---

## 目的

画面単位ではなく、「Forge を完成させるための工程」を共有する。

LP で発生した問題は、「画面を作ること」が目的化し、「Forge として何を完成させるのか」が見えなくなったこと。

今後の基本フロー:

```
ChatGPT
  ↓ UX設計
v0 モック
  ↓ レビュー
Cursor 実装
```

**LP 教訓**: overlay・座標合わせ・ピクセル一致は終了。v0 を正本にする。

---

## Phase0 — Forge 原典（完了）

**目的**: Forge とは何かを定義する。

**成果物**:

- 完成前のゲームとプレイヤーを繋ぐ PF
- Steam との違い
- 投稿 → 発見 → プレイ → FB → 改善 → 再プレイ
- 声 → 改善 → 再プレイ
- 応援ではなくフォロー
- ランキングは副次価値

**Cursor**: 判断に迷ったら必ず `docs/forge-principles.md` へ戻る。  
**画面の追加・変更**: `docs/forge-screen-definition.md` を正本として更新する。

## Phase1 — IA（情報設計）（ほぼ完了）

**成果物**: 01〜25 画面、画面遷移図、Studio 階層

**確定 — Studio**: 20 作品一覧 / 21 分析 / 22 作品情報 / 23 プレイヤーの声 / 24 開発ログ公開 / 25 作品設定

**確定 — プレイヤー**: 04〜18

**残課題**: プレイヤー Sidebar 最終確定、一部モック未受領

## Phase2 — UX 設計（現在ここ）

**目的**: ユーザーがどう体験するかを設計する。

**重要**: 画面を作ることが目的ではない。**体験を作る。**

### プレイヤー初回体験（最優先で完成させる導線）

```
LP
  ↓ 作品発見
  ↓ 作品詳細
  ↓ プレイ
  ↓ 声を届ける
  ↓ 変化を見る
  ↓ 再プレイ
```

### 開発者初回体験

```
登録
  ↓ 作品投稿
  ↓ 声を受け取る
  ↓ 改善
  ↓ 開発ログ公開
  ↓ 再プレイ獲得
```

### 継続利用体験

```
通知 → 戻る → 再プレイ
```

---

## Phase3 — UI 設計

**目的**: 体験をどう見せるかを設計する。ここで **v0** を活用。

```
ChatGPT で UX 整理
  ↓
v0 で画面作成
  ↓
レビュー
  ↓
Cursor 実装
```

LP のような overlay 地獄は繰り返さない。v0 を正本にする。

**01 LP**: オーナー OK 済（preview `/landing`、v0 正本写経）。

## Cursor への重要指示（2026-06-18）

1. **現在は Phase2（UX 設計）** — 次は「画面を実装すること」ではない
2. **最優先**: プレイヤー初回体験（LP → 発見 → 詳細 → プレイ → 声 → 変化 → 再プレイ）を**体験として**完成させる
3. **優先順位**: 画面番号順ではなく **コアループ順**
4. **正式フロー**: ChatGPT → v0 → Cursor
5. **LP**: v0 正本採用・OK 済。overlay / 座標合わせ / ピクセル一致は終了
