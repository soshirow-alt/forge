## P0-1. プロセスマップ全面再設計案

### 1-A. 二層構造（推奨）

Forge には **2 つの時間軸** がある。1 本の rail に無理に押し込まない。

**外側 — 作品ライフサイクル（1 回きり）**

```
投稿 → 公開中 → … → 正式版公開
```

**内側 — 改善ループ（繰り返し）**

```
回答を見る → 改善する → 変更を記録 → 新版公開 → （プレイヤー: プレイ・FB・変化を見る）
         ↑___________________________________________|
```

UI では **外側を細いステップバー（常時表示）**、**内側を太い現在地 rail（ループ中のみ強調）** とする。

### 1-B. オーナー指定 6 段フローへのマッピング

Studio `/projects/[id]/studio` の **主 rail（6 ノード）**:

| # | 表示ラベル | 意味 | データ / 状態 |
|---|-----------|------|----------------|
| 1 | **投稿** | 作品が Forge に存在 | 常に ✓（Studio にいる時点） |
| 2 | **公開中** | プレイヤーが遊べる | playable_version あり |
| 3 | **回答を見る** | 声が届いた | pendingFeedbackCount > 0 または read 工程 |
| 4 | **改善する** | 修正・記録前 | improving / devlog 工程 |
| 5 | **新版公開** | 版を届けた | publish 工程 / devlog publishedVersion |
| 6 | **正式版公開** | プロセス终点 | release_status released |

**ループ中**（3→4→5 の間）:
- ノード 3–5 を **ハイライト + ↺N**（第 N 回の改善）
- ノード 6 は **未到達**（outline）または **到達済**（✓ 固定）

**「反応を待つ」は rail から削除** — プレイヤー側の「再プレイ待ち」であり、開発者プロセスの工程名としては弱い。代わりに:
- ノード 5 完了後、Hero を **「プレイヤーの反応を待っています」**（状態コピー 1 行、説明段落ではない）
- またはノード 2「公開中」のサブラベルに **プレイ・FB 待ち**

### 1-C. Forge 価値との接続（ラベル下 1 語）

各ノード下に **プレイヤー視点の接続** を 1 語だけ（説明文禁止、rail 内 micro copy）:

| 工程 | micro（開発者 rail 下） |
|------|-------------------------|
| 公開中 | プレイヤーが来る |
| 回答を見る | フィードバック |
| 改善する | 改善 |
| 新版公開 | 再プレイ |
| 正式版公開 | 見届け |

これで **プレイ → フィードバック → 改善 → 再プレイ** が rail を見ただけで読める。

### 1-D. 正式版 — 独立カード廃止 → プロセス终点 CTA（推奨）

**現状**: `ProjectReleaseStudioPanel` が Studio 内の独立セクション（説明・placeholder・2 ボタン）

**案**:

1. プロセス rail **最終ノード「正式版公開」** が現在地のときだけ、Hero 下に **primary CTA 1 つ**
   - ラベル: **「正式版として公開する」**（名称は P1 正式版節参照）
2. クリック → **確認モーダル**
   - タイトル: 正式版として公開しますか？
   - 本文: 1–2 行のみ（例: この作品を正式版（Released）として宣言します。プレイヤーに正式版到達として表示されます。）
   - 任意メモ: 1 行 input（placeholder なし。ラベルのみ「メモ（任意）」）
   - 確定 / キャンセル
3. 成功 → rail ノード 6 を ✓ 固定。Reopened 時は 6 を「再調整中」に差し替え

**削除**:
- 独立 `#official-release` Studio パネルの枠
- 「この区切りについて〜」placeholder
- 長い説明 paragraph

**残す**:
- イベント履歴（折りたたみ 1 行「履歴 ▶」）— 開発者向け監査用

### 1-E. 一覧カード（作品管理）でのプロセス表示

`ProjectListCard` / 将来 `ForgeDeveloperProjectCard`:

- **5 段 micro rail**（投稿・公開中は常に ✓ 省略可）: `回答 · 改善 · 公開 · 正式版`
- **「いま: ○○」行は削除**（Studio に任せる）
- 現在地は **rail の ● 1 個** で示す

### 1-F. 文言変更一覧（`NURTURE_STEPS`）

| id | 現状 | 案 |
|----|------|-----|
| read | 回答を見る | **回答を見る**（維持） |
| improving | ゲームを修正する | **改善する** |
| devlog | 変更内容を記録する | **変更を記録** |
| publish | 新版公開する | **新版公開** |
| wait | 反応を待つ | **rail から削除**（Hero 状態のみ） |

`aria-label="育成サイクル"` → **`aria-label="公開までの流れ"`**  
`↺ サイクル N` → **`↺ 第 N 回`** または **`改善 N 回目`**

## P1-2. プレイ履歴案

### 折りたたみ

- **全カード初期折りたたみ**（`defaultExpanded={false}` 固定）
- 先頭のみ展開 — **禁止**

### 関係性バッジ（プレイヤー向け）

| 優先 | バッジ | 条件 |
|------|--------|------|
| 1 | 🏅 見届け人 | witness grant |
| 2 | 💬 FB投稿 | voiceCount > 0 |
| 3 | 🎮 最新版プレイ済 | 最新 playable_version で session あり |
| 4 | 🎮 複数版プレイ | distinctVersions >= 2 |

**削除**:
- `声を届けた` → **FB投稿**
- `更新を見た` → 削除（更新は `#updates` / バッジ不要）
- `▶️ プレイ済み` 最低バッジ → **最新版プレイ済** または FB/見届け人が無い場合のみ **プレイ済**

## P1-3. プレイヤー側セクション整理案（MECE）

### 問題: 現状 6 ブロックの重複

```
VoiceAdoptions / PlayHistory / Updates / Supported / Watching / Bookmarks / OfficialRelease
```

同一作品が **最大 4 セクション** に出うる（履歴 + 追跡 + 応援 + 正式版）。

### 推奨: 3 ブロック構成（2026-06-16 追加決定で更新）

```
/mypage（遊んだゲーム tab）

1. 新着（更新）          ← 旧「前回プレイ後の更新」。最上段（アクション必要）
2. 遊んだゲーム          ← 旧プレイ履歴 + 完成品到達を統合（🏆 完成品バッジ）
3. あとで遊ぶ            ← 保存作品 grid のみ（過剰分類しない）

※ フォロー中の開発者 — サイドバー責務（応援中は廃止）。block 3 に含めない
※ 更新を追う一覧 — 廃止（件数リンクのみ）
```

#### ブロック 1: **新着**

- 名称: **「あなたへの更新」** または **「新着」**
- 内容: 現 `MyPageUpdatesSection`（変更なし方向）
- 「更新を追う」**一覧セクションは廃止** — 追跡 ON/OFF は作品詳細のみ

#### ブロック 2: **遊んだゲーム**

- 名称: **「遊んだゲーム」**（旧プレイ履歴）
- 1 作品 1 カード（ForgeGameCard row + 折りたたみ timeline）
- **完成品到達** = カード上ワッペン **`🏆 完成品`**（開発中は原則ワッペンなし）+ フィルタ chip `完成品のみ`（任意）
- 旧 `#official-release` **独立セクション廃止** — 「完成品のみ」フィルタ時に grid 表示
- カードメタ（`forge-ui-product-decisions.md` §13）: 初回プレイ日 / 回数 / 最終版 / 更新あり / FB 済 / 見届け中 — **進捗率・クリア率は出さない**

#### ブロック 3: **あとで遊ぶ**

- ホームに近い **ゲームカード grid のみ**
- 折りたたみ optional（モック次第）
- **応援中セクションは廃止** → フォローはサイドバー「フォロー中の開発者」

#### VoiceAdoptions

- 現状維持（PLAYER_VISIBLE=false なら非表示のまま）
- 将来表示時も **遊んだゲーム** 内サブセクション候補

### MECE 表

| 問い | 答えが載る場所 |
|------|----------------|
| 何を遊んだ？ | 遊んだゲーム |
| 何が変わった？ | 新着 |
| 保存だけ？ | あとで遊ぶ |
| 完成品到達？ | 遊んだゲームの 🏆 完成品 / フィルタ |
| フォロー？ | サイドバー「フォロー中の開発者」（作品一覧ではない） |
| 版ごとの履歴？ | カード展開 timeline |

### 削除・統合サマリ

| 旧 | 新 |
|----|-----|
| プレイ履歴 | 遊んだゲーム |
| 正式版に到達した作品 | 遊んだゲームへ統合 |
| 応援中（独立 Dashboard） | **廃止** → フォロー中の開発者（サイドバー） |
| 更新を追っている（独立 Dashboard） | 廃止（件数リンクのみ） |
| あとで見る（独立 Dashboard） | あとで遊ぶ（block 3） |
