# Forge 追加決定事項（UI・情報設計）

**ステータス**: オーナー共有済み（2026-06-16）  
**リリース方針**: **正式リリース初期版** — 小さな MVP ではなく必要機能を初期から盛り込む  
**実装**: 画面モック → オーナー GO 後。**prod deploy 禁止**のまま  
**運用**: **画面モックを正**とし、本ドキュメントは **仕様・思想の補足**。矛盾時はオーナーに確認。

**関連**: `docs/ui-review-round2-design.md`、`docs/forge-screen-inventory.md`、`docs/forge-principles.md`（原典 — フォロー統合反映済み）、`docs/out-of-scope.md`

---

## 1. 作品カードの状態表示

- **開発中が通常状態** — 開発中作品に原則ワッペンを付けない
- **完成済みのみ** 作品カードに表示:

```
🏆 完成品
```

- 理由: 開発中を過剰強調しない。完成品だけ特殊状態として明示

**実装メモ**: 現行の Released / 正式版バッジ表現は **🏆 完成品** に寄せる。開発者向け工程ラベル（Studio rail）とは別レイヤ

---

## 2. 検索画面の責務分離

| 画面 | 検索対象 | フィルター例 |
|------|----------|--------------|
| **作品検索** | 作品名・説明・タグ・ジャンル等 | 完成品 / 開発中、ジャンル、プレイ環境 |
| **開発者検索** | **開発者名のみ** | 新規開発者 / 完成作品あり / 開発中作品あり |

- 開発者検索に **自己紹介・作品名・タグ・ジャンルは含めない**（検索汚染防止）

---

## 3. 開発者検索 — 新規開発者

- ワッペン: **🌱 新規開発者**
- 条件案: 初投稿から **30 日以内**
- フィルター: 新規開発者 / 完成作品あり / 開発中作品あり
- **表示しない**: 開発歴（「開発歴3年」等 — 先入観のみで価値薄）

---

## 4. 応援中 → フォロー中の開発者（統合）

| 旧 | 新 |
|----|-----|
| 応援（作品単位） | **フォロー（開発者単位）** |
| サイドバー「応援中」 | **「フォロー中の開発者」** |
| 応援ボタン | **フォロー** ボタン |

- 通知: フォロー中の開発者の **新作投稿 / Devlog 更新** 等
- **「応援中」サイドバー項目・画面は使わない**

**原典整合**: `forge-principles.md` **§ フォローと初声 — 2026-06 原典反映済み**

---

## 5. フォロワー数

- **開発者検索・開発者プロフィール** でフォロワー数表示 OK（開発者の参入動機）
- **ホーム / おすすめ** をフォロワー数だけで支配しない
- 並び替え許容: おすすめ順（**デフォルト**）/ フォロワー順 / 新着順 / 作品数順

---

## 6. 新規開発者を守る — 作品魅力の2軸

プレイヤー動機は **「面白そう」** だけでなく **「自分の声が影響を与えられそう」**。

| 軸 | 強い信号 |
|----|----------|
| A. おもしろそう | 完成度が高い |
| B. 影響を与えられそう | 初期作品・新規開発者・見届け人/FB が少ない |

**作品カード・詳細で B を表現**（例）:
- 見届け人が少ない
- FB がまだ少ない
- 開発者が今悩んでいること
- 方向性が固まりきっていないこと

---

## 7. フィードバック「共感」

- 文言: **共感**
- 対象: **自由記述 FB のみ**（選択式には付けない）
- 集計:
  - 共感は **FB 投稿数に加算しない**
  - **声の大きさ / AI 集約の重み** には反映
  - 例: 1 件の自由記述 + 15 共感 → 投稿数 1、賛同 16 人相当

---

## 8. 開発者による FB 評価（非公開）

- 開発者のみ: 届いた FB を **「開発に役立った」** と内部評価
- **ユーザーには見せない**（全員に押す圧力を避ける）
- 用途: 影響度スコア、月間ランキング、将来バッジ

---

## 9. 月間影響度ランキング

- 名称: **月間影響度ランキング**（旧「月間見届け人ランキング」は**誤表記** — 2026-06-16 オーナー訂正）
- 毎月リセット。過去入賞は **バッジ・称号** として残す
- 評価: FB 投稿数だけで決めない。**開発者評価 + 共感 + 継続見届け + 新人貢献** を組み合わせ（影響度スコア）
- **開発者検索には出さない** — サイドバー「ランキング」または発見系別画面

**スコープ**: **正式リリース初期版に含む**（`docs/out-of-scope.md` 2026-06 更新 — 旧 out-of-scope 解除）

---

## 10. 影響度スコア（ユーザーに見せる価値）

見せたいのは **「たくさんコメントした人」** ではなく **「開発者に信頼される見届け人」**。

加点例:
- 開発に役立った（開発者評価）
- 自由記述 FB に共感
- FB が改善に反映
- 同作品を継続見届け

投稿数だけは強く評価しない

---

## 11. フィードバック履歴画面

- **FB タイトル不要**
- カード優先: 作品名 / 回答日時 / 自由記述本文（あれば必ず表示）/ 選択式は質問+回答 1–2 / 共感数 / 改善反映有無
- 選択式が多い場合は全部出さない — 詳細 or 「続きを読む」

---

## 12. 返信文化

- 開発者返信は **あってよい**
- **使わない**: 「返信待ち」「未回答」
- 重視: 共感された / 改善で反映された / 開発に役立った

---

## 13. プレイ履歴画面

**表示しない**（ゲーム内部進捗は Forge で見えない）:
- 達成率 / 進行率 / クリア率

**表示する**:
- 見届け中か
- フォロー中の開発者の作品か
- 初回プレイ日 / プレイ回数 / 最後に遊んだバージョン
- 更新あり
- FB 送信済みか

---

## 14. あとで遊ぶ

- 責務: **保存した作品の一覧のみ**
- ホームに近いゲームカード grid。**過剰分類しない**

---

## 15. 実績画面

- **残す** — ただし活動サマリーにしない
- 表示: 獲得済み / 未獲得 / 解放条件 / 進行状況（**実績・バッジのみ**）
- **置かない**: FB 数 / 共感数 / 応援数 / プレイ時間 / 活動記録 / 円グラフ

---

## 16. 通知一覧

- 横幅を広げすぎない — **中央に適度な幅の通知カラム**、右に余白
- 一覧性優先

---

## 17. Studio Sidebar 正本（2026-06-16 オーナー確定）

**採用**: 階層型 Sidebar。**同列構造は不採用**（作品 A/B が分からなくなるため）。

**比喩**: GitHub — Repository → Issues / Pull Requests / Settings

### Level 1（Studio 共通 — 作品未選択 or 横断）

| 項目 | 画面 |
|------|------|
| 作品一覧 | **20** |
| 分析ダッシュボード | **21** |

### Level 2（作品選択後）

| 項目 | 画面 |
|------|------|
| 作品情報 | **22** |
| プレイヤーの声 | **23** |
| 開発ログ公開 | **24** |
| 作品設定 | **25** |

```
20 作品一覧
  ↓ 作品選択
22 作品情報
23 プレイヤーの声
24 開発ログ公開
25 作品設定
```

**不採用**（旧案）:

```
作品一覧 / プレイヤーの声 / 開発ログ / 作品設定（同列）
```

**理由**: 作品単位管理と全体分析を分離するため。

**モック整合**: 22B 左サムネ作品リストは **Level 2 の作品切替 UI** として可。Level 1 に声・ログ・設定を並べないこと。

**21 分析の入口**（2026-06-16 追撃確定）: **Studio Level 1 のみ**（作品一覧 / 分析ダッシュボード）。**global 配置不要** — 分析は開発者活動の一部、プレイヤー導線と切り離す。

**廃止**: 旧 **20 Studio ホーム** / 旧 **リリース管理**（→ 24）/ 旧 **開発ログ管理**（→ 24）

## 18. 21 分析ダッシュボード と 22 作品情報 — 責務分離（2026-06-16 確定）

**重要**: **21 と 22 で同じ統計を並べない。**

### 22 作品情報 — 作品運営画面

| | |
|--|--|
| **対象** | **単一作品**（例: 星灯の旅路） |
| **見る単位** | 作品 |
| **表示例** | 作品情報 / 最新 Devlog / プレイヤーの声サマリー / 次にやること / クイックアクション |

### 21 分析ダッシュボード — 全作品経営ダッシュボード

| | |
|--|--|
| **対象** | 開発者の**全作品** |
| **見る単位** | 開発者全体 |
| **表示例** | 作品別フォロワー推移 / 作品別プレイ数推移 / 声の推移 / 開発活動推移 / 全体傾向 |

| 22 | 21 |
|----|-----|
| 作品管理 | 全体分析 |
| ハブ・次アクション | 横断トレンド |

### 22「次にやること」（2026-06-16 追撃確定）

**専用 Task DB は作らない** — MVP でも正式版でも Notion / Trello / Jira 型のタスク管理機能は out。

22 の「次にやること」は **以下から生成する表示**（程度の提案リスト）:

| 優先 | ソース |
|------|--------|
| ① | 最新のプレイヤーの声 |
| ② | **開発に役立った** と評価された FB |
| ③ | AI 要約 |
| ④ | 直近 Devlog |

**例**: チュートリアル改善を検討 / 戦闘テンポ見直し候補 / 説明不足の指摘あり

**Forge の目的**: タスク管理ではなく **声 → 改善** の循環。

## 19. 実装 GO 順（2026-06-16 オーナー確定）

**原則**: ランキングから先に作らない。Forge のコアは **声 → 改善 → 再プレイ**。ランキングは副次価値。

### Phase 1 — Shell（**Studio 先行・プレイヤーと同時 NG**）

| サブ | 内容 | 備考 |
|------|------|------|
| **1-A** | **Studio Shell** — 20 / 21 / 22 / 23 / 24 / 25 | **最優先**。Sidebar / Header / Nav / Route + **階層 nav**（§17） |
| **1-B** | **Player Shell** — 09–18 | **1-A 後**。`/mypage` タブ → 独立画面 + Sidebar / Header |

**理由（1-A 先行）**:
- 構造変更の本丸は Studio（同列 nav → 階層 nav）。影響範囲が大きい
- プレイヤー側は `/mypage` タブから 09–18 へ分離する程度

**旧 Phase 2「Studio 階層化」** → **1-A に包含**（Shell と同時に階層 nav を実装）

### Phase 2 以降

| Phase | 内容 | 備考 |
|-------|------|------|
| **2** | **開発者フォロー DB** — 応援 → 開発者フォロー | §4 |
| **3** | **23 プレイヤーの声** — 開発に役立った / AI 要約 / 質問集計 | |
| **4** | **08 フィードバック送信** — 質問 → 自由記述 | |
| **5** | **18 月間影響度ランキング** | **最後** — 共感・開発に役立った・フォロー・継続見届けに依存 |

**依存関係**: Phase 5 以前に共感・開発者評価・フォロー・見届けのデータ/UI 基盤が必要。

### `/` 入口（2026-06-16 オーナー確定 — 実装は Phase1-B 以降）
