# P1-2.6 ゲーム育成サイクル UI — ワイヤーフレーム

**ステータス**: 実装完了（deploy 待ち）  
**前提**: P1-2.5 deploy 済み（dpl_BmY7mgTEqocGqSUDNVvgd6GXzy59）。オーナー本番 UX で「改善は感じるが、一瞬で次が伝わらない」→ **状態説明 UI が4分割で重複**が原因。

---

## 0. P1-2.5 の残課題（オーナー FB 整理）

P1-2.5 で解消したこと:
- FB inbox 型から作品一覧ファーストへ
- 現在地 / 次の概念導入
- FB を「プレイヤーの声」に格下げ

P1-2.5 で残ったこと:
- **現在地・次にやること・成長ステップ・改善サイクル** が別ブロック → 同義情報の4重表示
- 情報量は多いが視線が散る → 「状態説明 UI」が強い
- 「次何をすればいいか」が **一瞬** では伝わらない

P1-2.6 の目的:
上記4要素を **1つの「ゲーム育成サイクル」コンポーネント** に統合し、**今ここ / 次ここ** を視覚的に一発で伝える。

---

## 1. 設計原則

1. **1作品 = 1サイクル UI** — 現在地/次/ステップ/サイクル履歴をここに集約
2. **文言ラベルより位置** — 「今」「次」はノードの強調で伝える
3. **完了 = グレー** / **今 = 強調** / **次 = 最強調 + Primary CTA**
4. **詳細はクリック** — ノード tap で FB / devlog / 版 / 履歴を開く
5. **循環** — 反応待ち →（再プレイ）→ FB へ戻る矢印を明示（Forge は何度も回す）
6. **過去3ステップ** — 投稿・発見・プレイはサイクル外縁の小さな足跡（1行 or 3dot）

---

## 2. 統合コンポーネント — `GameGrowthCycle`

### 2-1. 役割

| 廃止（P1-2.5 カード内） | 統合先 |
|---|---|
| dl「現在地」「次にやること」 | サイクル上の **今** / **次** ノード |
| GrowthStepMini / GrowthStepDetail | サイクル本体 |
| 改善サイクル（前回/今回/次） | **改善** ノード click 時の詳細パネル |
| 展開 Hero「次にやること」見出し | **次** ノード直下の1行 + CTA |

残す（サイクル外・展開内）:
- 開発状況（版/devlog/応援）— コンパクト1行 or **新版公開** ノード詳細
- プレイヤーの声 — **FB** ノード click で開く

---

### 2-2. ループ構造（中心）

```
        ┌─────────┐
        │   FB    │◀──────────────┐
        └────┬────┘               │
             ↓                    │ 改善サイクル N+1
        ┌─────────┐               │
        │  改善   │               │
        └────┬────┘               │
             ↓                    │
        ┌─────────┐               │
        │新版公開 │               │
        └────┬────┘               │
             ↓                    │
        ┌─────────┐               │
        │反応待ち │───────────────┘
        └─────────┘
```

過去（サイクル外・上部1行）:
`✓投稿 · ✓発見 · ✓プレイ` （すべて gray、クリックで詳細可）

---

### 2-3. ノードの視覚状態

| 状態 | 見た目 | 例 |
|---|---|---|
| **完了** | gray、✓、細線 | 既に通過した FB / 改善 |
| **今ここ** | orange ring、中字号、「今」バッジ | 改善フェーズ中 |
| **次ここ** | 最亮（orange fill or glow）、大字号、「次」バッジ | 次は新版公開 |
| **未到達** | zinc-700 破線、低コントラスト | 反応待ち（まだ） |

**一瞬で伝えるためのルール**
- カード折りたたみ時: **次** ノードだけがカード幅の 40% 程度を占める（最大）
- **今** ノードはその左隣、小さめ
- 完了ノードはアイコン程度に縮小
- テキストラベル「現在地:」「次にやること:」は **表示しない**（ノード内短ラベルのみ）

│                     ↑              ↑                             │

└──────────────────────────────────────────────────────────────────┘

**一覧で読み取る情報（0.5秒）**
1. 作品名
2. ループ上の **今** と **次** の位置
3. **次** の動詞（改善版を作る / 新版を公開する / 反応を待つ）
4. Primary ボタン1つ

**一覧で見せないもの**
- 現在地/次の dl 2行
- mini ステップ + 別 improve サイクル 3行
- FB 本文

### 4-1. ノード click → 詳細パネル

| ノード | 開く内容 |
|---|---|
| FB | プレイヤーの声（最新 + 過去折りたたみ） |
| 改善 | 改善サイクル 前回/今回/次 + devlog 一覧リンク |
| 新版公開 | 最新版号、版公開 devlog、/devlog/new |
| 反応待ち | copy「プレイヤーの再プレイと新 FB を待っています」+ 作品詳細 |
| 投稿/発見/プレイ | 作品詳細 / 編集（過去ステップ） |

詳細パネルは **1箇所**（サイクル直下）。複数セクションを縦に並べない。

## 5. 状態 → サイクル上の「今」「次」マッピング

P1-2.5 の `buildProjectGrowthSnapshot` ロジックは **維持**し、UI マッピングのみ変更。

| 内部状態 | 今（current node） | 次（next node） | Primary CTA |
|---|---|---|---|
| FB 0件 | プレイ（または FB） | FB | 作品詳細 |
| FB 受領・devlog 未 | FB or 改善 | **改善** | 開発ログを書く |
| devlog 済・版未 | 改善 | **新版公開** | 新版を公開する |
| 版公開済 | 新版公開 | **反応待ち** | なし |
| 新 FB 再到着 | FB | **改善** | 開発ログを書く |

**次ノードの表示文案（汎用、P1-2.5 継続）**
- 改善版を作る
- 新版を公開する
- プレイヤーの反応を待つ
- プレイヤーに見つけてもらう
