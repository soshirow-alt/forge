# 本番 E2E 確認 — 新版公開 → 再プレイ → 新FB

**目的**：Forge 原典コアループの最後「再プレイ → 新FB」が**本番環境で成立したこと**を、非エンジニアでも再現・確認できるようにする。

**対象 URL**：https://forge-flame-gamma.vercel.app

**関連**：`docs/version-published-loop-design.md` / `docs/supabase-dashboard-migration-guide.md` §005

---

## 0. なぜ今これを優先するか

- 版公開ループの**コードは実装済み**だが、**本番で成立した実績がない**
- Forge 原典ループ（投稿→…→改善→**再プレイ→新FB**）の最後の 1 節が、本番未確認のままでは「MVP として成立」と言えない
- **extras DB 化より先**にやる理由：extras は「情報が消えない」運用改善。本 E2E は「成長ループが回る」**コンセプトそのもの**の確認。ループ未成立のまま DB 化を進めても、プレイヤーが新版に戻らない根本問題は残る

---

## 1. 事前条件チェックリスト

実施前に **すべて** 満たしていることを確認する。

### 1-1. インフラ

| # | 条件 | 確認方法 |
|---|---|---|
| 1 | **migration 005 適用済み** | Supabase Dashboard → SQL Editor で `user_notifications` に `published_version` 列がある。type に `version_published` が入る（§1-4 参照） |
| 2 | **005 対応コードの deploy 完了** | 005 **より後** に Vercel 本番 deploy（または redeploy）済み |
| 3 | **適用順序が正しい** | **005 → deploy**（逆だと版 bump 時に通知 insert が失敗する） |

005 未適用のまま deploy している場合：**E2E は必ず失敗する**。先に 005 を適用し、必要なら redeploy してから本手順へ。

### 1-2. アカウント・ブラウザ

| # | 条件 | 理由 |
|---|---|---|
| 4 | **テストアカウント 2 つ** | 開発者（A）とプレイヤー（B）を分ける |
| 5 | **別ブラウザ or シークレット** | 同一ブラウザだとログインが上書きされる |
| 6 | A = テスト作品の**オーナー** | devlog・版 bump はオーナーのみ |
| 7 | B ≠ A | 通知は**自分自身には送らない**実装のため |

**1 アカウントのみの場合**：版 bump まで開発者側は確認可。**通知・バナー・新 FB は B が必要**（後述 §6 簡易確認）。

### 1-3. テスト作品

| # | 条件 | 理由 |
|---|---|---|
| 8 | **Supabase に投稿された実作品** | mock 作品（emberfall 等）は **通知対象外** |
| 9 | **公開（public）** | 非公開は B から見えない |
| 10 | 作品 URL をメモ | 例：`/games/xxxxxxxx`（UUID）または `/games/消えるかな` |
| 11 | **現行プレイ可能版をメモ** | 作品詳細または開発ダッシュボードで確認。例：`0.1` |

本番の実作品例：「消えるかな？」（オーナー投稿）。mock だけでは **本 E2E 不可**。

### 1-4. 005 適用の簡易 SQL 確認（任意・Dashboard）

SQL Editor で Run：

```sql
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_schema = 'public'
  AND table_name = 'user_notifications'
  AND column_name IN ('type', 'published_version');
```

`published_version` 行が返れば OK。

### 1-5. プレイヤー（B）側の状態（版 bump **前**）

| # | 条件 | 画面での見え方 |
|---|---|---|
| 12 | B でログイン | ヘッダーに B の名前 |
| 13 | **更新を追う** 済み | 作品詳細サイドバー「**更新を追跡中**」（オレンジ枠） |
| 14 | **プレイ済み** | 「プレイする」クリック済み（外部 URL へ遷移可） |
| 15 | **現行版向け FB 投稿済み** | 例：版 `0.1` 向けに FB 送信済み。「フィードバックを送信しました」表示 |
| 16 | 現行版向け FB は**編集モードでも可** | バナー条件は「現行版 FB 無し」なので、bump 前に 0.1 FB があること |

**バナーが出ない典型**：watch していない / FB 未投稿 / すでに新版 FB 済み。

### 1-6. 開発者（A）側の状態（版 bump **前**）

| # | 条件 |
|---|---|
| 17 | A でログイン、テスト作品のオーナー |
| 18 | 新版名を決めておく（現行版と**異なる**）。例：現行 `0.1` → 新版 `0.2` |

## 2. 実施手順

**所要時間目安**：15〜20 分（初回）

### フェーズ A — プレイヤー（B）準備 【版 bump 前】

**B のブラウザ**で https://forge-flame-gamma.vercel.app を開く。

| Step | 操作 | クリック / 入力 |
|---|---|---|
| A-1 | ログイン | ヘッダー **ログイン** → B のメール/パスワード → ログイン |
| A-2 | 作品詳細を開く | トップまたはマイページから **テスト作品** をクリック |
| A-3 | 更新を追う | 右サイドバー **更新を追う** → **更新を追跡中** に変わる |
| A-4 | プレイする | **プレイする** → 外部タブでプレイ URL が開く（数秒で閉じてよい）→ 作品詳細タブに戻る |
| A-5 | FB 投稿 | ページ下部 **プレイ後フィードバック** → 任意の内容を入力 → **送信** |
| A-6 | FB 成功確認 | 「**フィードバックを送信しました**」と表示。版表記が現行版（例 `0.1`） |
| A-7 | 状態メモ | 「B: watch 済 / プレイ済 / 版 0.1 FB 済」と記録 |

**期待結果（フェーズ A 終了時）**

- サイドバー：**更新を追跡中**
- FB：**0.1 向け送信済み**
- 通知：**まだ**「新しいプレイ可能版」は**来ない**（正常）

---

### フェーズ B — 開発者（A）版 bump 【ここでループの「新版公開」】

**A のブラウザ**（B とは別）で操作。

| Step | 操作 | クリック / 入力 |
|---|---|---|
| B-1 | ログイン | A アカウントでログイン |
| B-2 | 開発ダッシュボード | ヘッダー **開発ダッシュボード** |
| B-3 | 開発ログを書く | 対象作品行の **開発ログを書く** |
| B-4 | タイトル・内容 | **今回の更新タイトル** / **今回の更新内容** を入力 |
| B-5 | 新版公開 ON | **今回の更新を新しいプレイ可能版として公開する** にチェック |
| B-6 | 版名入力 | **プレイ可能版のバージョン名** に `0.2` 等（現行と**別名**） |
| B-7 | 投稿 | **投稿する**（または同等の送信ボタン） |
| B-8 | 遷移確認 | 作品詳細 `/games/{id}` に戻る |
| B-9 | 開発の歩み | **開発の歩み** に今回の devlog + 版ラベル（`0.2` 等） |

**期待結果（フェーズ B 終了時）**

- devlog 投稿**成功**（エラー赤枠なし）
- 作品のプレイ可能版が **0.2** に更新（詳細またはダッシュボードで確認）
- A 自身には **version_published 通知は来ない**（自分は watch 対象から除外 — 正常）

**失敗しやすい点**：005 未適用で deploy 済み → devlog は成功するが **B に通知が来ない**（§4 参照）。

---

### フェーズ C — プレイヤー（B）通知 → バナー → 再プレイ → 新 FB

**B のブラウザ**に戻る。

| Step | 操作 | クリック / 入力 |
|---|---|---|
| C-1 | 通知を開く | ヘッダー **通知**（未読数があれば `(1)` 等） |
| C-2 | 一覧更新 | 開いた直後に一覧が空なら **ページを再読み込み**（F5）。Realtime なし |
| C-3 | 通知確認 | 種別 **新しいプレイ可能版** の行がある |
| C-4 | メッセージ確認 | 例：「〇〇のプレイ可能版 0.2 が公開されました。もう一度プレイして…」 |
| C-5 | 通知タップ | その行をクリック |
| C-6 | 詳細遷移 | `/games/{id}#new-playable-version-banner` が開く |
| C-7 | バナー確認 | 概要の**直下**に**オレンジ色**のバナー。「新しいプレイ可能版 0.2 が公開されました」 |
| C-8 | 再プレイ | 右サイドバー **プレイする** → 外部 URL |
| C-9 | FB フォーム | ページ下部までスクロール。**プレイ可能版 0.2** 向け、フォームが**空**（新版用） |
| C-10 | 新 FB 送信 | 内容入力 → **送信** |
| C-11 | バナー消失 | ページ再読み込み後、オレンジバナーが**表示されない** |
| C-12 | 編集確認 | 同じ 0.2 向け FB は再表示時**編集モード**（旧 0.1 内容が混ざらない） |

**期待結果（フェーズ C = E2E 成功）**

| チェック | 成功の見え方 |
|---|---|
| 通知生成 | B の `user_notifications` に 1 件（Dashboard 確認は任意） |
| 通知一覧 | `/notifications` に「新しいプレイ可能版」 |
| 詳細遷移 | 通知クリックで作品詳細へ |
| オレンジバナー | 概要下、`#new-playable-version-banner` |
| 新版 FB フォーム | 版 `0.2` 表記、入力欄が空 |
| FB 投稿後 | バナー消える、0.2 FB 送信済み |

## 4. 失敗時の切り分け

### 4-1. 通知が来ない（B）

| 原因候補 | 確認方法 | 対処 |
|---|---|---|
| **005 未適用** | Dashboard で `published_version` 列なし | 005 適用 → redeploy |
| **005 前に deploy** | 版 bump 時 A 側で devlog 成功だが B に通知なし | 005 適用後、**もう一度**版 bump（0.3 等） |
| **mock 作品でテスト** | 作品 ID が mock slug のみ | **Supabase 投稿作品**で再実施 |
| **B が watch していない** | 詳細で「更新を追う」のまま | B で watch してから A が bump |
| **A と B が同一アカウント** | 1 人で両役 | 別アカウントで B 操作 |
| **通知ページ未更新** | 一覧が空 | **F5 再読み込み**（Realtime なし） |
| **watch ユーザー 0 人** | B が bump 前に unwatch | 再度 watch → 再 bump |

### 4-2. バナーが出ない（B・通知は来た）

| 原因候補 | 確認方法 | 対処 |
|---|---|---|
| **watch していない** | 「更新を追う」表示 | watch する |
| **旧版 FB 未投稿** | 0.1 FB なし | 先に旧版 FB → 再 bump |
| **すでに新版 FB 済み** | 0.2 FB 送信済み | 正常（バナー不要）。別版で再テスト |
| **現行版 = 旧 FB 版** | bump 失敗で版が変わっていない | A 側 devlog + 新版チェック確認 |
| **ログアウト** | 未ログイン | B でログイン |

### 4-3. FB フォームが切り替わらない（旧版内容のまま）

| 原因候補 | 確認方法 | 対処 |
|---|---|---|
| **playable_version 未更新** | 詳細の版表記が 0.1 のまま | A の devlog 新版チェック・版名確認 |
| **未プレイ** | FB セクション自体が出ない | **プレイする** をクリック |
| **キャッシュ** | 版は 0.2 だが表示が古い | **F5** またはシークレットで再確認 |

### 4-4. devlog 投稿自体が失敗（A）

| 原因候補 | 対処 |
|---|---|
| Supabase 未設定 / セッション切れ | 再ログイン、env 確認 |
| 004 未適用 | migration 004 適用 |
| 版名が現行と同じ | 別名（0.2 等）を入力 |

## 6. 1 アカウントのみの簡易確認（参考）

通知・バナー・新 FB は **別プレイヤー必須**。1 アカウントでは以下まで：

| 確認できる | 確認できない |
|---|---|
| devlog + 新版 bump | B への version_published 通知 |
| playable_version 更新 | オレンジバナー（旧版 FB + watch 条件） |
| 開発の歩みに版表示 | 新版向け空 FB フォーム（別ユーザー前提） |
