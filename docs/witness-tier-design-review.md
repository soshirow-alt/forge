# 見届け人 tier — 設計レビュー（草案）

**ステータス**: 設計レビュー（**実装 GO 前**）  
**日付**: 2026-06-16  
**前提**: W4 マイページ UI GO、014 適用、PLAYER_VISIBLE=false 維持

**Out**: tier 実装、作品詳細、人数表示、ランキング、通知

---

## 1. 目的

作品単位の「見届け人」（W4）に加え、**横断的な育成の記録**をプレイヤー自身に返す。

Forge 原典:

- 件数競争 NG — 「最多見届け人」ランキングは作らない
- 伴走の証 — レビュー王・採用率王ではない

tier は **自分のプロフィール / マイページ** 向け。他人との比較 UI は Out。

---

## 2. 暫定案（オーナー 2026-06-16）

| tier | 条件（案） | 名称（暫定・要再検討） |
|------|------------|------------------------|
| 1 | 見届け人 grant **1 作品** | 見届け人 |
| 2 | 見届け人 grant **3 作品** | 見届け人 Silver |
| 3 | 見届け人 grant **10 作品** | 見届け人 Gold |

**カウント**: `project_witness_grants` の **distinct project_id**（ユーザーあたり）。剥奪なし — 累計のみ。

**命名再検討の方向**

- 「Silver / Gold」はゲーム実績っぽく競争感が出やすい
- 代替案: **見届け人** / **見届け人・なじみ** / **見届け人・古参**（`player-badges-design-review.md` 案に近い）
- または数字を出さず **「3 作品を見届けました」** テキストのみ（tier バッジなし）

---

## 3. 表示方針（案）

| In | Out |
|----|-----|
| マイページ — 自分の tier / 累計作品数（静かな一文） | 作品詳細「見届け人 N 人」 |
| プロフィール — 自分のみ | リーダーボード |
| 「N 作品の正式版を見届けました」 | 「トップ 10%」 |

**文言例（件数競争を避ける）**

- 1 作品: 「正式版まで見届けた作品があります」
- 3 作品: 「複数の作品の正式版を見届けてきました」
- 10 作品: 「多くの作品の育ちに関わってきました」

※ 具体コピーは tier 実装前にオーナー確定。

---

## 4. DB / 判定

**追加 migration 不要（案 1）** — 実行時集計:

```sql
SELECT COUNT(*) FROM project_witness_grants WHERE user_id = $1;
```

**案 2（将来）** — `user_witness_tier_grants` append-only（tier 到達イベント）。通知や履歴が要る場合のみ。

推奨: **Phase 1 tier = 集計のみ**（014 正本の grant 行を数える）。
