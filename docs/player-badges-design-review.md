# プレイヤーバッジ設計レビュー

**ステータス**: 設計レビュー（**実装 GO 前** — オーナー判断 2026-06-15）  
**日付**: 2026-06-16  
**前提**: voice_adoptions matcher 完成 → Phase3 再プレイ hook → プレイ履歴 → **バッジ設計** → バッジ実装

---

## 0. オーナー判断（確定）

- バッジ導入は **GO**。ただし **今は実装しない**
- Forge の評価軸は「良いレビュー」ではなく **「伴走」**
- **件数競争は禁止**（採用率王・レビュー王・FB件数王・バグ件数王 — すべて NG）
- 最上位候補（現時点）: **見届け人** — ただし **単純 1 回プレイ NG**
- 見届け人条件候補: 声を届けた / 複数版プレイ / 継続して追っていた（今後詳細化）
- **正式版** = 開発者宣言（semver 不可）。`docs/official-release-design.md`
- 優先順位: staging 精度 → matcher 本番 GO → Phase3 → 履歴 → 正式版 → バッジ詳細 → バッジ実装

---

## 1. バッジの目的

| 目的 | 説明 |
|------|------|
| **市場活性化** | 作品が育つ過程に人が集まり、離脱しない |
| **継続参加** | 「また来よう」と思える理由を、数値競争ではなく **関係性** で作る |

**Forge 価値との接続**

- 本体: 「俺が言ったことが変わった」（voice_adoptions）
- バッジ: 「俺がこのゲームを **育てた** / **見届けた**」の **長期の証**

バッジ単体で因果を作らない。adoption 行と再プレイが先、バッジは **後から付く名誉**。

---

## 2. NG 方向（避ける）

以下は **採用しない**:

- 採用率ランキング
- レビュー王 / FB件数王 / バグ報告数ランキング
- 週間・月間「最も役立った声」Top N
- 開発者への「星5レビュー」数

**理由**

- Forge が **「レビュー職人ゲーム」** になる
- 自由記述の質より **量・形式** が最適化される
- 「伴走」と矛盾する — 短期スコア最大化は **再プレイ・改善サイクル** を弱める

**原典整合**: `docs/forge-principles.md` — ランキングは MVP スコープ外（AGENTS.md も同旨）

---

## 3. Forge らしい方向 — 5 候補

### ① 見届け人（最優先候補）

**意味**: 作品が **正式版** に到達するまで伴走した

**正式版の定義**: 開発者が Studio で **Released** を選択（semver 1.0 自動判定 **NG**）。詳細 `docs/official-release-design.md`。

| 段階 | 条件案 | 表示名案 |
|------|--------|----------|
| Bronze | 正式版到達 **1 作品** | 見届け人 |
| Silver | 正式版到達 **3 作品** | 見届け人・熟練 |
| Gold | 正式版到達 **10 作品** | 見届け人・古参 |

**参加条件（オーナー方針 — 詳細は今後）**

単純な 1 回プレイ **だけ** では付与しない。候補:

- 声を届けた（voice 回答）
- 複数 playable_version をプレイ
- 継続して watch / 再訪

**付与タイミング（確定）**

- **初回 `Released` で付与**
- **`Release Reopened` 後も剥奪しない** — 見届けた事実は消えない（`docs/official-release-design.md`）

**データ要件**

- `projects.release_status` / `released_at`（将来 migration）
- プレイ履歴（版ごと）
- voice_adoptions / voice_responses

**UX**

- プロフィール / マイページに静かに表示
- 作品詳細に「見届け人 N 人」ランキング — **Out**

**懸念**

- 正式版宣言の取り消し — 実装前に要設計

---

### ② 伴走者

**意味**: **同じ作品** を複数バージョンで継続プレイした

| 段階 | 条件案 |
|------|--------|
| 1 | 同一 project で **2 以上の playable_version** をプレイ |
| 2 | 同一 project で **5 以上** の版をプレイ |
| 3 | voice 回答後の **再プレイ**（Phase3 hook ログ）を 1 回以上 |

**データ要件**

- プレイ履歴（版ごと）
- Phase3: `?adoption=` 経由の再プレイ（将来）

**Forge 価値**

- 「更新のたびに戻ってきた」= 育成の主体

---

### ③ 育成者

**意味**: voice_adoptions が **累計** で N 件（自分の声が反映された回数）

| 段階 | 条件案 |
|------|--------|
| 1 | 累計 **1** 件（初回 adoption） |
| 2 | 累計 **5** 件 |
| 3 | 累計 **20** 件 |

**注意**

- **採用率** ではなく **累計件数** — 率ランキング NG との線引き
- dispute で suppressed になった行は **カウントから除外**
- indirect / direct を区別して見せない（プレイヤーには通常 adoption と同じ）

**データ要件**

- `voice_adoptions` where `status = active` and `user_id = self`

---

### ④ 発掘者

**意味**: **初期プレイヤー** として参加した

| 条件案 |
|--------|
| 作品の **最初の N 人**（例 50 人）の voice 回答者 or プレイヤー |
| または playable_version `0.1` / 初回公開から **30 日以内** の参加者 |

**Forge 価値**

- 「最初から一緒にいた」感 — インディー支援の文脈

**懸念**

- 人数上限 N は作品規模で調整が必要
- 後から参加した人が永久に取れない → **1 作品 1 回限り** で公平性は保たれる

---

### ⑤ 常連

**意味**: **継続プレイ回数**（Forge 全体または作品横断）

| 段階 | 条件案 |
|------|--------|
| 1 | 累計 **10** セッション |
| 2 | 累計 **50** |
| 3 | **30 日間で 5 日以上** ログイン＋プレイ |

**懸念**

- セッション定義（同一日複数回は 1 カウント等）要設計
- 作品横断だと「量」寄りになりやすい → **伴走者・見届け人より優先度低**

---

## 4. 優先順位（バッジ内）

| 順位 | バッジ | 理由 |
|------|--------|------|
| 1 | **見届け人** | オーナー最上位候補。「完成まで伴走」が Forge  narrative と一致 |
| 2 | **伴走者** | 再プレイ hook と直結。版を追う行動を褒める |
| 3 | **育成者** | voice_adoptions 蓄積後に自然。因果の蓄積 |
| 4 | **発掘者** | 初期支援の物語。データは比較的取りやすい |
| 5 | **常連** | 汎用。競争化リスクを監視しつつ後回し |

---

## 5. 実装前の依存（なぜ今やらないか）

| 依存 | 用途 |
|------|------|
| **matcher 完成** | 育成者バッジの正本データ |
| **Phase3 再プレイ hook** | 伴走者の「adoption 後再プレイ」判定 |
| **プレイ履歴** | 伴走者・常連・発掘者の版/日時 |
| **正式版マイルストーン** | 見届け人の終点定義 |

**In（将来）**

- バッジ定義テーブル + ユーザー獲得記録
- マイページ / プロフィールの静的表示
- 通知でのバッジ獲得 **は慎重**（スパム化しやすい → 初回のみ or Out）

**Out**

- ランキング UI
- バッジ比較・リーダーボード
- 開発者 Studio での「採用率」表示
- 今スプリントでの実装

---

## 6. 表示原則（UX）

- バッジは **自分のプロフィール** が主。他人との比較 UI は作らない
- 獲得時コピーは **伴走** 語彙（「見届けました」「一緒に育てました」）
- 「可能性があります」等の弱い表現は adoption UI と同様 **NG**
- バッジ説明文に AI / matcher の話は **不要**（adoption セクションの disclaimer で足りる）

## 7. オーナー確認論点（設計段階）

1. **正式版の定義** — 開発者手動マーク vs `1.0` 自動 vs 両方
2. **見届け人の参加条件** — watch のみ / voice 必須 / 1 回プレイ必須
3. **育成者累計** — 同一作品の複数 adoption は全部カウントで OK か
4. **発掘者 N** — 50 人固定 vs 作品規模連動
5. **バッジ獲得通知** — 要 / 不要 / 初回のみ
