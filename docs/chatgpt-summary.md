■ Forge原典コアループ
- 回答を見る → ゲーム修正（Forge外）→ 変更記録 → 新版公開 → 反応を待つ
- 今回 UI がこの流れと競合しないよう Hero / サイクル / CTA を統一

■ 今回実装したこと
1. 育成サイクル: ゲームを修正する / 変更内容を記録する / 新版を公開する
2. Studio Hero: 回答後フェーズで「プレイヤーの回答が届きました」「次はゲームを修正しましょう」
3. ゲーム修正モーダル + localStorage「次回から表示しない」
4. その他のやること = 質問を編集する / 作品情報を編集する のみ
5. 「この作品を育てる」→「作品を更新する」
6. 作品管理: 要対応セクション削除、カード状態バッジ強化
7. プレイヤー活動: 「3つのリストの違い」削除

■ 今回変更した画面
- /projects/{id}/studio
  - Hero CTA / 育成サイクル / その他のやること / 修正説明モーダル
  - 変更前: 開発ログを書く CTA が先に出て Forge外修正が伝わらない
  - 変更後: フェーズに沿った Hero + 修正モーダル
- /mypage?tab=developer 作品一覧
  - 要対応セクション廃止、バッジで状態表示
- /mypage プレイヤー活動
  - 用語説明ブロック削除
- 作品カード / 所有者 sidebar
  - CTA「作品を更新する」

■ なぜこの文言
- 「作品を更新する」: オーナー推奨。studio へ進み版・記録・公開サイクルを回す行為と一致
- 「ゲームを修正する」: Forge外作業を明示（原典どおり Forge は修正場所ではない）
- 「変更内容を記録する」: devlog=記録工程であることを開発ログより直球に

■ ユーザー目線の変化
- 開発者: studio で「今何をすべきか」が1本の流れで分かる
- 補助操作（質問・作品情報）は副次導線に退避

■ In / Out
- In: 文言・Hero・モーダル・補助導線整理・カードバッジ
- Out: DB、deep feedback 通知、FAQ/ヘルプページ

■ 本番確認観点
1. studio: 未読回答 → Hero「回答を見る」→ 読了後「ゲームを修正する」+ モーダル
2. モーダル「次回から表示しない」→ 再クリックでモーダル非表示、サイクル improving パネル展開
3. その他のやること = 2項目のみ
4. 作品管理: 要対応セクションなし、バッジ表示
5. プレイヤー活動: 説明ブロックなし
