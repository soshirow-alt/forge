# Forge 情報設計（IA）見直しレビュー

> ステータス: オーナーレビュー用（**実装 GO 前**）  
> 日付: 2026-06-15  
> 背景: Phase2 #6 本番確認 → **入口が増えすぎてノイズ化** → #6 **一旦停止**、サイト全体 IA から再整理

---

## 0. 本レビューの結論（先に）

1. **#6 現行案（Banner + main フォーム + sidebar + mobile bar）は採用しない** — 同じ行為の入口が 3〜4 つになり、「どこで何をするか」が逆に分かりづらい。
2. **IA を固めてから画面単位最適化する** — 開発者・プレイヤーとも「詳細ページに全部載せる」構造をやめる。
3. **プレイ後の初声は「1 回限りの軽いオーバーレイ」が第一候補** — × で閉じられる。後から答える場合のみ詳細 sidebar から。
4. **開発者は `/games/{id}` から編集・問い設定に直行しない** — 育成ハブ（`/my-projects` → 作品育成）経由が理想形。
5. **用語は「改善につながる声」に統一** — 「評価」と「返事」の人工的な対比は不要。原典の **声を届ける** を軸に整理。

**#6 コード（commit 64b481f）**: main に push 済みの可能性あり。**IA 確定まで追加の #6 作業は停止**。必要なら revert または「次 IA 実装で置換」をオーナー判断。

## A. Forge サイトマップ（理想形）

### A-1. 二つの視点

Forge は **同じ URL でも役割が違う画面** を持つ。プレイヤー向け「作品詳細」と開発者向け「育成」は **別 IA** として設計する。

```
                    ┌─────────────────────────────────────┐
                    │           公開（ログイン不要）          │
                    │  /  /games/*  /creators/*           │
                    └─────────────────────────────────────┘
                                      │
              ┌───────────────────────┴───────────────────────┐
              ▼                                               ▼
    【プレイヤー視点】                               【開発者視点】
    発見→プレイ→声→変化→再プレイ                      投稿→育成→声→改善→再公開
              │                                               │
              ▼                                               ▼
    /mypage  /bookmarks  /notifications              /my-projects  /submit
                                                     /projects/*/edit  /devlog/new
```

### A-2. 画面一覧とループ上の位置

| URL | 名称（案） | 主な利用者 | ループ上の段 | 現状 |
|---|---|---|---|---|
| `/` | 発見（ホーム） | 全員 | 発見 | 実装済 |
| `/games/{id}` | **作品詳細（プレイヤー画面）** | プレイヤー | 発見・プレイ・変化を見る | 実装済。**開発者機能が混在** |
| （新）プレイ後オーバーレイ | **声を届ける（初回）** | プレイヤー | 声を届ける | **未実装**（#6 で詳細埋め込みを試したが停止） |
| `/mypage` | マイページ | プレイヤー | 再プレイ・追跡 | 実装済（プレイ履歴・ブックマーク等） |
| `/bookmarks` | あとで見る | プレイヤー | 発見 | 実装済 |
| `/notifications` | 通知 | 両方 | 変化を見る | 実装済 |
| `/login` | ログイン | 全員 | — | 実装済 |
| `/submit` | 作品投稿 | 開発者 | 投稿 | 実装済（問い設定含む） |
| `/my-projects` | **開発マイページ / 育成ハブ** | 開発者 | 育成・声を見る | 実装済（P1-2.7 育成カード。**本格 IA 未完了**） |
| `/projects/{id}/edit` | 作品編集 | 開発者 | 改善（設定） | 実装済。**詳細からもリンクあり（問題）** |
| `/projects/{id}/devlog/new` | 開発ログ | 開発者 | 改善・再公開 | 実装済 |
| `/creators/{id}` | クリエイター | 全員 | 発見 | 実装済 |
| `/demo` | デモ | 内部 | — | 実装済 |

**将来検討（Phase3 以降・URL は案）**

| URL（案） | 名称 | 役割 |
|---|---|---|
| `/my-projects?focus={id}` または `/projects/{id}/studio` | **作品育成ページ** | 1 作品の「やること一覧」ハブ |
| `/projects/{id}/voice`（開発者のみ） | 声の確認 | 集計・解釈・深い FB 受信箱 |

### A-3. プレイヤーサイクル × 画面

```
発見        → /  , /games/{id}
プレイ      → /games/{id} sidebar「プレイする」
声を届ける  → 【プレイ直後オーバーレイ】 primary
              → /games/{id} sidebar「声を届ける」 secondary（後から）
変化を見る  → /games/{id}「開発の歩み」「みんなの声」、/notifications
再プレイ    → /games/{id}「もう一度プレイ」、/mypage
```

### A-4. 開発者サイクル × 画面

```
投稿        → /submit
育成        → /my-projects（入口）
声を見る    → /my-projects 作品育成ブロック（集計・解釈・深い FB）
改善する    → 問い再設定 /projects/{id}/edit、devlog /projects/{id}/devlog/new
再公開      → devlog 経由で playableVersion bump
```

**原則**: 開発者の「次にやること」は **`/games/{id}` ではなく `/my-projects`** に集約する。

## B. 開発者導線の理想形

### B-1. 各画面の責務

| 画面 | 責務（やること） | やらないこと |
|---|---|---|
| **マイページ `/mypage`** | プレイヤーとしての履歴・ブックマーク・追跡中作品 | 作品編集・問い設定・集計管理 |
| **開発マイページ `/my-projects`** | 作品一覧、**いま育てる 1 作品**の提示、サイクル位置、Primary CTA 1 つ | プレイヤー向け詳細の代用、問いフォーム編集の本体 |
| **作品育成ページ**（ハブ内フォーカス or 専 URL） | **やること一覧**: 声を見る / 問いを見直す / devlog / 編集 / 詳細をプレビュー | 初声フォーム、プレイヤー CTA |
| **作品編集 `/projects/{id}/edit`** | メタ情報、公開設定、**版プレイヤー問い設定**、サムネ等 | FB inbox 本体、サイクル全体像 |
| **問い設定** | edit 内セクション（独立 URL 化は後回し可） | プレイヤー回答 UI |
| **声確認** | my-projects 内: 集計・解釈・深い FB（個別は非公開） | 公開詳細への個別回答流出 |
| **Devlog** | 改善記録 + 版公開 | 問い編集の主画面 |
| **作品詳細 `/games/{id}`**（開発者が自分の作品を見る場合） | **プレイヤー体験のプレビュー** のみ。小さな「開発者: 育成ページへ」リンク | primary「編集する」、問い設定、inbox |

### B-2. 理想ナビゲーション

```
開発マイページ (/my-projects)
  │
  ├─ 作品 A ──► 作品育成（フォーカス）
  │                 ├─ [Primary] 開発ログを書く / 声を読む（状態依存）
  │                 ├─ 声を見る（集計・解釈）
  │                 ├─ 問いを設定 ──► /projects/A/edit#prompts
  │                 ├─ 投稿を編集 ──► /projects/A/edit
  │                 └─ プレイヤーにどう見える？ ──► /games/A（プレビュー）
  │
  └─ 作品 B …
```

### B-3. 現状とのギャップ

| 問題 | 現状 | 理想 |
|---|---|---|
| 詳細→編集直行 | sidebar / 開発者メニューに「編集する」 | 育成ページ経由。詳細はプレビューリンクのみ |
| 声の確認場所 | my-projects + 詳細の「みんなの声」混在 | 開発者の読解は my-projects。詳細の集計はプレイヤー向け |
| Primary CTA 散在 | 投稿・編集・devlog・FB が各所 | **1 画面 1 Primary**（P1-2.5 原則を本格適用） |
| サイクル可視化 | P1-2.7 ワイヤあり、未統合 | 作品育成ページの主役 UI |

**Phase3（#1 育成ハブ）** = 上記 B-2 の本格実装。P1-2.5 / P1-2.7 の設計資産を統合して着手。

## C. プレイヤー導線の理想形

### C-1. 各要素の責務

| 要素 | 責務 | 配置（理想） |
|---|---|---|
| **詳細ページ** | 作品理解、プレイ開始、**みんなの声（集計）**、**開発の歩み（変化）** | main 列の本体 |
| **プレイ** | ログイン → プレイ確認 → 外部/埋め込み起動 → プレイ記録 | sidebar Primary（未プレイ時） |
| **プレイ後の声（初声）** | 開発者の問いに **1 問以上** 任意回答。改善の材料になる | **プレイ直後オーバーレイ**（第一入口） |
| **後から声** | オーバーレイを閉じた人向け | sidebar「声を届ける」**1 つだけ** |
| **深い FB** | 熱量高い人の任意追加 | 初声完了後、折りたたみ。**詳細 main 最下部 or オーバーレイ内 secondary** |
| **みんなの声** | 集計・傾向（個別非公開） | 詳細 main。**読むだけ**。入力ではない |
| **変化を見る** | devlog・新版認知 | 詳細「開発の歩み」+ 通知。**未実装 UI 多い** |

### C-2. 詳細ページ main 列（理想）

```
Overview
（新版バナー — あれば）
説明
みんなの声        ← 読む（集計）
開発の歩み        ← 変化を見る
（深い FB — 初声完了者のみ、折りたたみ）
```

**含めない（理想）**

- PostPlayFeedbackBanner（main 上部 CTA）
- GameVoiceSection 本体の常時 embed（played_pending でも main に出さない）
- mobile sticky bar（オーバーレイと sidebar で足りる）

### C-3. 詳細 sidebar（理想・状態別）

| 状態 | Primary | Secondary |
|---|---|---|
| 未プレイ | プレイする | watch / bookmark |
| プレイ済・声未完了 | **声を届ける**（1 つ） | もう一度プレイ |
| 声完了 | （muted）届けました | 再プレイ / もっと詳しく（任意） |

**開発者向けリンクは sidebar に置かない** — ヘッダー「開発ダッシュボード」または詳細フッターのテキストリンク程度。

### C-4. プレイ直後オーバーレイ（オーナー案の整理）

```
┌ プレイありがとう ─────────────── × ┐
│ 開発者から質問があります            │
│ 「{先頭問い 1 行}」                 │
│                                     │
│ [ ひとこと答える ]  [ あとで ]      │
└─────────────────────────────────────┘
```

| 原典要件 | オーバーレイでの満たし方 |
|---|---|
| プレイ前に初声を出さない | プレイ記録後のみ表示 |
| モーダルで阻まない | × / あとで で即閉じる。**ページ操作をブロックしない**（ログイン modal とは別物） |
| 1 問で完了 OK | オーバーレイ内で 1 問回答 → 完了 |
| 全問強制 NG | 残り問いは詳細 sidebar から任意 |
| レビューサイト化 NG | 集計公開のみ。オーバーレイは入力 UI |

「ひとこと答える」→ オーバーレイ内に **VoicePromptCard 1 画面**（または全問スクロール可だが 1 問 submit で完了）。

## D. 用語整理

### D-1. オーナー補足の反映

> 「評価してください」と「返事を届ける」の違いを無理に作る必要はない。  
> 重要なのは **その声が改善につながること**。

### D-2. 提案するユーザー向け語彙（1 軸）

| 概念 | 推奨 copy | 使わない |
|---|---|---|
| プレイヤー行為（全体） | **声を届ける** | 評価する、レビュー、アンケート、感想を送る（乱立時） |
| 初声完了 | **声を届けました** | 返事を届けました / フィードバック完了（混在回避） |
| 開発者の問い | **開発者からの質問** | アンケート、評価項目 |
| 深い任意入力 | **もっと詳しく（任意）** | 改善材料を全部 |
| 公開集計 | **みんなの声** | レビュー一覧 |
| 開発者側 | **プレイヤーの声** | FB inbox（ユーザー向け文言） |

**「返事を届ける」vs「声を届ける」**: 原典 §5 は両方使用。IA 上は **「声を届ける」に統一**し、オーバーレイ見出しのみ「開発者から質問があります」と文脈補足。**同一 CTA を文言違いで 3 回出さない**。

### D-3. 応援との関係（変更なし）

応援 = 感情 / 初声 = 情報。**統合しない**（原典維持）。sidebar では visual secondary のまま。

## E. #6 を含めるべきか — 3 案比較

### E-1. 現行 #6 案（64b481f — 停止）

| 項目 | 内容 |
|---|---|
| 概要 | main reorder + Banner + embed フォーム + sidebar 3 状態 + sticky bar + 選択肢 affordance |
| 意図 | プレイ後にフォームを近づける |
| 本番所感 | **入口 3 つ**（sidebar / Banner / main フォーム）→ ノイズ |
| 判定 | **不採用**（方向修正） |

### E-2. 案 B — プレイ後オーバーレイ + 詳細は sidebar のみ（**推奨**）

| 項目 | 内容 |
|---|---|
| 概要 | プレイ直後:  dismissible オーバーレイで初声。詳細: sidebar 1 入口 + main は読むだけ |
| #6 から残す | VoicePromptCard affordance、sidebar 3 状態、用語統一 |
| #6 から捨てる | main Banner、main embed フォーム、mobile sticky bar、main reorder |
| 原典整合 | ◎ プレイ→声、非強制、任意深い FB |
| IA 整合 | ◎ 詳細＝理解・プレイ・変化。声＝別モーメント |
| リスク | オーバーレイ実装（focus trap しない設計要） |
| 工数感 | 中（#6 の半分再利用 + オーバーレイ新規） |

### E-3. 案 C — 詳細内 1 箇所に集約（Banner も sidebar も廃止）

| 項目 | 内容 |
|---|---|
| 概要 | プレイ後のみ main 上部に **1 ブロック**（Banner+フォーム一体）。sidebar はプレイ/再プレイのみ |
| メリット | 入口 1 つに単純化 |
| デメリット | 詳細を開いただけでは未プレイと見た目が変わる。オーナー「ポップアップ自然」意向とずれる |
| 判定 | 次点（オーバーレイが難しい場合の fallback） |

### E-4. 推奨まとめ

```
Phase2 次着手 = 「IA-first 初声」= 案 B
  1. 開発者 IA: Phase3 育成ハブ（B 章）を先にラフ確定
  2. プレイヤー IA: 詳細から voice embed 除去方針確定
  3. オーバーレイ初声 UI 設計 → 実装
  4. #3 テンプレート分離は IA 後でも可（独立度高い）
```

**#6 番号の扱い**: 中身を **「#6b IA-first 初声（オーバーレイ）」** に差し替え、旧 #6 は **#6a（詳細埋め込み — 却下）** として記録。
