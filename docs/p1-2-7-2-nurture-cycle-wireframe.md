## 1. 設計原則（P1-2.7.2）

1. **サイクルが主役** — タスク管理 UI ではなく「育てている」画面
2. **3 問に常時答える**
   - **今どこ？** — 現在の段階（視覚的ノード）
   - **次は？** — Hero が示す行動（次のイベント）
   - **この先？** — 未完了ステップが右（または下）に見える
3. **Why は短く常時** — 各ステップ下に 2〜4 文字の目的ラベル（読まなくても periphery で理解）
4. **Hero はサイクルから切り離さない** — 「今の段階 → 次の行動」の接続を見せる
5. **Rail 1 行テキストは廃止** — 進捗として認識される **ノード UI** に戻す

### 5 段 + Why（共通マイクロコピー）

| 段 | ラベル | Why（常時表示） |
|---|---|---|
| read | FBを読む | 声を聞く |
| improving | 改善する | 直す |
| devlog | 開発ログを書く | 記録する |
| publish | 新版公開する | 届ける |
| wait | 反応を待つ | 育つ |

内部状態 `improving` は維持。UI ラベルは **改善する**。

## 3. 案 A — 横型サイクルトラック（推奨）

### コンセプト

作品カードの **上半分をサイクル**、下半分を **行動** に割く。  
Hero は「次のイベント」、トラックは「今の位置とこの先」。

### ワイヤ — 改善中フェーズ（Emberfall 例）

```
┌─ Emberfall ─────────────────────────────── v0.3 · ↺2 ─┐
│                                                         │
│  育成サイクル                                            │
│                                                         │
│  [✓ FB]────[● 改善]────[○ devlog]────[○ 公開]────[○ 待]│
│   声を聞く   直す        記録する     届ける      育つ    │  ← Why 常時
│              ↑いま                                      │
│                                                         │
│  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─   │
│                                                         │
│  次にやること                                            │
│  開発ログを書く                          text-2xl white │
│  改善が終わったら、記録してプレイヤーに届けましょう       │  ← Why 1行（短）
│                                                         │
│  [ 開発ログを書く ]                        orange CTA   │
│                                                         │
│  作品詳細 · 編集 · 応援 12                               │
└─────────────────────────────────────────────────────────┘
```

### ワイヤ — FB 未読（Neon Drift 例）

```
│  [● FB]────[○ 改善]────[○ devlog]────[○ 公開]────[○ 待]│
│   声を聞く   直す        記録する     届ける      育つ    │
│   ↑いま                                                 │
│                                                         │
│  次にやること                                            │
│  FBを読む                                               │
│  届いた声が、次の改善の材料になります                      │
│  [ FBを読む ]                                           │
```

### ノード状態（視覚）

| 状態 | 見た目 | 意味 |
|---|---|---|
| done | ✓ + グレー塗り or チェックのみ | 通過済み（click で振り返り） |
| now | ● + やや明るい面 | **今どこ** |
| next | 細 ring or → 矢印強調 | **Hero が指す次**（now≠next のとき） |
| future | ○ + 薄い | **この先** |

**改善中の now/next 分離**
- **now** = ● 改善する（状態・作業中）
- **next** = devlog ノードに subtle ring（Hero は devlog 行動）
- 接続線: `改善 ──→ devlog` 区間をやや明るく（「この先こうなる」）

### 一覧スキャン（3 作品）

```
Emberfall      [✓][●改善][○][○][○]  →  開発ログを書く
Neon Drift     [●FB][○][○][○][○]    →  FBを読む
Starbound      [✓][✓][✓][✓][●待]    →  反応を待つ
```

2 行目（Hero 動詞）で比較、1 行目（トラック）でサイクル位置を比較。

### 長所 / 短所

| 長所 | 短所 |
|---|---|
| 5 段 + ↺ が常に見える | モバイルは折り返し or 短ラベル必要 |
| Why がノード下で常時 | P1-2.7.1 より縦幅 +40px 程度 |
| Hero とサイクルの関係が線で見える | |

## 7. Cursor 推奨

**第一推奨: 案 A（横型サイクルトラック）**

- P1-2.7.1 の Hero 主役は維持
- サイクルを **カード上部 1 ブロック** に復活（主役級の視覚重量）

- P1-2.7.1 の 1 行 Rail テキストは **置き換え**

**Hero 補助行（案 A 用・例）**

| フェーズ | Hero | 補助 1 行（Why） |
|---|---|---|
| FB 未読 | FBを読む | 届いた声が、次の改善の材料になります |
| 改善中 | 開発ログを書く | 改善が終わったら、記録して届けましょう |
| 公開待ち | 新版公開する | 記録した改善を、プレイヤーに届けましょう |
| 反応待ち | 反応を待つ | 新しい声が届いたら、またサイクルが回ります |
| 2 周目 FB | FBを読む | {n} 周目 — また声が届きました |
