## 低コスト vs 構造的問題

### 低コスト（数時間〜1日、既存画面の copy / 小 UI 変更）

| 項目 | 内容 | 根拠 |
|---|---|---|
| **UX-2** devlog ラベル | 「タイトル」→「今回の更新タイトル」。placeholder・補足文を追加（例：「プレイヤーに伝える今回の変更点の見出し」） | `devlog-new-page.tsx` の label 変更のみ |
| **UX-4** ログイン Enter | 本番で再現確認。`login-page.tsx` は既に `<form onSubmit>` あり → 再現すれば `password` の Enter ハンドラ or フォーム構造の微修正 | 1 ファイル |
| **投稿完了画面** | 成功後 CTA を「次にやること」順に：`開発ログを書く`（primary）→ 作品詳細 → ダッシュボード | `submit-page.tsx` の link 順・文言 |
| **my-projects 行アクション** | 各作品に `[開発ログを書く]` `[FBを見る]` を表の操作列に追加（新 route 不要） | `my-projects-page.tsx` |
| **ホームタブ subtitle 強化** | 既存 subtitle の見せ方改善、タブ下に 1 行説明を常時表示 | `home-page.tsx` copy のみ |
| **004 関連 copy** | playable_version 表示位置の改善は copy+1 行追加レベル（概要欄に現行版） | 前回 verification より |

### 構造的問題（設計判断＋複数画面・新 route の可能性）

| 項目 | 内容 | なぜ構造か |
|---|---|---|
| **UX-1** 作品ダッシュボード | 作品単位の「育てる場所」がない。`/games/[id]` はプレイヤー向け UI が主 | 新 page `/projects/[id]` or dashboard 相当、ナビモデル変更 |
| **UX-1** 開発者 vs プレイヤー画面分離 | オーナーは「作品詳細」ではなく「作品ダッシュボード」を期待 | IA（情報設計）の再定義 |
| **UX-3** ホーム discovery タブ | 「新着」「テストプレイ受付中」の意味が Forge 文脈とズレ | タブ定義・フィルタロジック・投稿フォーム `lookingForTesters` との一貫性 |
| **ダッシュボード全体** | `/my-projects` は作品一覧表＋全体 FB inbox。作品別 stats・次アクションが弱い | ページ目的の再設計 |

## 優先順位（Cursor 提案）

### P0 — MVP として今すぐ（次スプリント）

| 順 | 項目 | 理由 |
|---|---|---|
| 1 | **UX-2** devlog ラベル・説明 | コアループ「改善」の入口。迷いが直接 devlog 投稿を止める |
| 2 | **投稿完了 → 次アクション** | 投稿直後が最も「次に何を？」が発生する瞬間 |
| 3 | **my-projects に作品別 CTA** | 新 page なしで UX-1 の 60% をカバー |
| 4 | **UX-4** ログイン Enter | 毎セッションの摩擦。低コスト |

### P1 — MVP 直後（軽い設計判断を含む）

| 順 | 項目 | 理由 |
|---|---|---|
| 5 | **UX-3** ホームタブ copy 再整理 | プレイヤー初回体験。まず説明改善、効果見てタブ統合を判断 |
| 6 | **playable_version / 新 FB 導線 copy** | 004 コアループの「次の FB」が分かりにくい（前回 verification） |
| 7 | **オーナー向け作品詳細バナー** | オーナーが `/games/[id]` を開いたとき「開発者メニュー」へ誘導 |

### P2 — 後回しでよい（構造変更・产品判断待ち）

| 項目 | 理由 |
|---|---|
| **作品単位ダッシュボード新設** | 効果大だが route・UI 新規。P0/P1 で様子見 |
| **ホームタブ統合・廃止** | `lookingForTesters` の产品価値をオーナーと再定義してから |
| **開発者/プレイヤー画面完全分離** | P1 バナー＋CTA で足りるか検証後 |
| **アナリティクス / SDK セクション** | 既に Coming Soon。MVP 外 |
| **旧版 FB プレイヤー表示** | 004 で意図的に後回し |

## Forge MVP として「今直すべきもの」

**テーマ**: 「何をすればいいか」を **言葉とボタン** で答える（新機能なし）

1. **開発者の次アクションを明示**
   - 投稿完了：「① 開発ログを書いて改善を共有 → ② プレイヤーの FB を見る」
   - ダッシュボード：作品ごとに `[開発ログを書く]` `[FBを見る]` `[編集]`
2. **devlog フォームのラベル・説明**
   - 何を書く画面か、各項目が何を指すか
3. **ログイン Enter**（再現確認のうえ修正）
4. **ホームタブ** — 最低 1 行の説明追加（統合は P2）

**狙い**: オーナーが触って感じた「探す・迷う」を、**画面追加なしで半分減らす**。
