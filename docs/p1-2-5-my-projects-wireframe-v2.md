# P1-2.5 作品育成ハブ版 — ワイヤーフレーム（v2）

**ステータス**: オーナーレビュー待ち（実装 GO 前）  
**前提**: Forge は FB 管理ツールではなく **ゲーム育成ツール**。開発者は「FB を見に来る」のではなく「ゲームを育てに来る」。

---

## 0. 情報設計の骨格（最重要）

```
【第1層】作品一覧     … どの作品を育てるか（ファーストビュー）
    ↓ 作品選択（展開 / focus）
【第2層】作品育成     … 選んだ作品を育てる（FB はここで材料として後段）
```

**禁止する順序（P1-2 / v1 案の問題）**

```
作品一覧 → FB inbox → 育成   ✗
作品一覧 → 次にやること(FB件数) → FB全文 → 育成   ✗
```

**採用する順序**

```
作品一覧（現在地 + 次にやること 優先）
    ↓
作品育成ビュー（展開）
    1. 次にやること（Hero CTA）
    2. 開発状況（版 / devlog / 改善サイクル）
    3. プレイヤーの声（最新 FB + 過去折りたたみ）
```

FB は **第3セクション**。「新FB 3件」は badge 程度。主語は常に **作品の成長**。

## 1. ファーストビュー（ページ全体）

### 1-1. ヘッダー帯

```
← 作品一覧に戻る

開発ダッシュボード
ゲームを育てる場所です。プレイヤーの声は、次の版を作るための材料です。

                                    [ + 作品を投稿 ]  ← tertiary（小・outline またはテキスト）
                                                         作品0件時のみ gradient Primary
```

**CTA ルール（ページヘッダー）**

| 状態 | 「作品を投稿する」 |
|---|---|
| 作品 0 件 | **Primary**（gradient） |
| 作品 1 件以上 | **Tertiary**（右上小ボタン or テキストリンク） |
| いずれかの作品に未対応 FB あり | ヘッダーに Primary を置かない。Primary は各作品カード内 |

---

### 1-2. ファーストビューの主コンテンツ = **作品一覧のみ**

スクロール初期画面に表示するのは **作品育成カードのリスト** のみ。

- 横断 NextActionsPanel **なし**
- 横断 FB inbox **なし**
- アナリティクス / SDK は **一覧の下**（スクロール後）

**ソート（一覧）**

1. 要対応あり（未対応 FB → devlog 未書き）を上
2. 同一優先度内は最終更新 desc

**複数作品時のファーストビューで伝えること**

> 「どの作品を育てるか」— 各カードの **現在地** と **次にやること** で判断できる

## 2. 作品一覧 — コンパクトカード（折りたたみ・常時表示）

各作品 = 1 枚の **育成サマリカード**。  
サムネ + メタ + **現在地/次** が視線の中心。FB 件数は補助。

### 2-1. カードレイアウト（折りたたみ時）

```
┌─────────────────────────────────────────────────────────────────┐
│ [サムネ 64px]  だもんでとなんもんでの冒険                          │
│                                                                 │
│                ┌─ 現在地 ─────────────────────────────────────┐ │
│                │ プレイヤーから FB を受領                      │ │
│                └──────────────────────────────────────────────┘ │
│                ┌─ 次にやること ───────────────────────────────┐ │
│                │ 操作感改善版を作る                            │ │  ← 最大字号・semibold
│                └──────────────────────────────────────────────┘ │
│                                                                 │
│  最新版 0.1 · 最終更新 6/14 · 応援 12 · 改善サイクル 2            │  ← 1行メタ（小）
│                                                                 │
│  [過去] 投稿 発見 プレイ ｜ [現在地] FB━━ 改善 ○ 新版 ○ 反応 ○   │  ← ステップ mini
│                                                                 │
│                                              [ この作品を育てる ] │  ← Secondary（outline）
└─────────────────────────────────────────────────────────────────┘
```

**折りたたみ時に見せないもの（意図的に隠す）**

- FB 本文
- devlog 本文
- 複数 CTA

**折りたたみ時に見せる補助情報（小さく）**

- 新 FB 件数 → 「未対応 FB 1件」程度の **1行テキスト**（badge 単体を主役にしない）
- 最新版 / 最終更新 / 応援 / 改善サイクル数

---

### 2-2. 現在地 / 次にやること — 状態マトリクス

一覧・展開の **両方** で同じロジック。表示文言は作品ごとに1セット。

| 現在地（現在） | 次にやること | Primary CTA（展開時） | 備考 |
|---|---|---|---|
| 投稿したばかり | プレイヤーに見つけてもらう | 作品詳細を確認 | 発見・プレイ待ち |
| プレイヤー待ち | 最初の FB を待つ | 作品詳細をシェア | FB 0 件 |
| プレイヤーから FB を受領 | ○○版を作る（具体化） | **開発ログを書く** | ○○ = 最新 FB の concerns 要約 or 汎用「改善版」 |
| 改善を記録済み | 新版を公開する | **新版を公開する** | devlog あり・版未更新 |
| 新版を公開した | プレイヤーの反応待ち | 作品詳細を見る | 再プレイ・新 FB 待ち |
| （新 FB 到着） | ○○版を作る | **開発ログを書く** | サイクル N+1。現在地が FB 受領に戻る |

**「次にやること」の具体化（MVP）**

- 汎用文案で可: 「改善版を作る」「操作感改善版を作る」
- 理想: 最新 FB の `concerns` 先頭 20 文字から自動（AI 要約は Out）
- 常に **動詞 + 目的** の形。FB 件数は出さない

## 3. 作品選択 → 作品育成ビュー（展開時）

「この作品を育てる」tap / アコーディオン展開 / `?focus={id}` で同一ページ内に **作品育成ビュー** を表示。  
**新 URL（案 C）は作らない。**

### 3-1. 展開ビュー — セクション順（固定）

```
① 作品ヘッダー（タイトル + サムネ + メタ1行）
② 次にやること（Hero — ページ内最重要）
③ 成長ステップ（ループ主役）
④ 改善サイクル（文脈・履歴）
⑤ 開発状況（版 / devlog / 応援）
⑥ プレイヤーの声（FB — 材料）
⑦ 補助リンク（詳細 · 編集 · 削除）
```

**FB が主役にならない理由**: ⑥ が最後。② の Hero が「開発ログを書く」「新版を公開する」。

---

### 3-2. セクション② 次にやること（Hero）

```
┌─ 次にやること ─────────────────────────────────────────────────┐
│                                                                 │
│   操作感改善版を作る                                             │  ← 大見出し（FB件数ではない）
│                                                                 │
│   プレイヤーから届いた声をもとに、開発ログで改善を記録しましょう。   │
│                                                                 │
│   [ 開発ログを書く ]  ← 唯一 Primary（gradient）                 │
│                                                                 │
│   作品詳細 · 投稿を編集                    ← tertiary テキスト     │
└─────────────────────────────────────────────────────────────────┘
```

**状態別 Hero 文案**

| 次にやること | Primary ボタン |
|---|---|
| ○○版を作る | 開発ログを書く |
| 新版を公開する | 新版を公開する → `/projects/{id}/devlog/new` |
| プレイヤーの反応待ち | （Primary なし）Secondary: 作品詳細 |
| プレイヤーに見つけてもらう | Secondary: 作品詳細 |

---

### 3-3. セクション③ 成長ステップ

**前半3（過去）— 小さく・1行・完了済み muted**

```
  ✓投稿  ✓発見  ✓プレイ          ← 12px, zinc-600, 横並び compact
  ─────────────────────────
```

**後半4（ループ主役）— 大きく・現在地 highlight**

```
  ┌────┐   ┌────┐   ┌────────┐   ┌────────┐
  │ FB │ → │改善│ → │新版公開│ → │反応待ち│
  └────┘   └────┘   └────────┘   └────────┘
    ●        ◉          ○            ○
  完了     現在地      未達         未達
```

- 現在地 1 箇所のみ orange accent
- ループ完了（反応待ち → 新 FB）で FB が再点灯、改善以降リセット
- ゲームポイント・順位・バッジ **なし**

**タップ（完了済みステップ）**

| ステップ | 遷移 / 展開 |
|---|---|
| 投稿 / 発見 | 作品詳細 |
| プレイ | 作品詳細（プレイヤー視点） |
| FB | ⑥ プレイヤーの声へスクロール |
| 改善 | ⑤ 開発状況 devlog 一覧 |
| 新版公開 | 最新 devlog（版公開済み） |
| 反応待ち | 作品詳細 |

---

### 3-4. セクション④ 改善サイクル（文脈表示）

競わせない。履歴と文脈。

```
┌─ 改善サイクル 2 ────────────────────────────────────────────────┐
│                                                                 │
│  前回    移動速度改善        （devlog: 5/28 公開 → v0.1）        │
│  今回    操作感改善          （devlog 下書き or FB受領後）        │
│  次      再プレイ待ち        （新版公開後に表示）                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

- 「サイクル 2」= ラベルのみ。他ユーザーとの比較 UI なし
- 前回/今回 = 直近 devlog タイトル or 版公開メモ
- 次 = 現在地マトリクスと連動

┌─ 開発状況 ──────────────────────────────────────────────────────┐

## 6. ファーストビュー vs 展開 — 視線フロー

```
[入室]
  ↓
作品A: 次=操作感改善版を作る  ← 最優先視線
作品B: 次=反応待ち

  ↓ タップ「この作品を育てる」

  ↓

  ↓

  ↓
プレイヤーの声（材料）  ← 最後
```

## 8. オーナー確認ポイント（ワイヤレビュー用）

1. ファーストビューが **現在地/次** 中心で、「FB件数」が主役になっていないか
2. セクション順 **次→開発状況→声** で FB 格下げが十分か
3. ステップ **3小+4大** のバランス
4. 改善サイクル「前回/今回/次」の文案
5. 展開: アコーディオン vs `?focus=id`
6. 一覧で **サムネ** 必須か（Game に image あり — 表示可）
7. 「次にやること」の具体化レベル（汎用 vs FB 先頭文字）

## 9. v1 案からの変更点

| v1（FB 残存） | v2（育成ハブ） |
|---|---|
| 新FB N件を badge 主役 | 現在地 + 次にやることを主役 |
| 横断 inbox / Panel | 廃止。作品内「プレイヤーの声」のみ |
| 7 ステップ同 weight | 3 小 + 4 ループ大 |
| 改善サイクル N のみ | 前回/今回/次 の文脈 |
| 一覧と FB が同段 | 一覧 → 選択 → 育成の3層 |
